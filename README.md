# 📖 NovelMaestro

Конвейер перевода китайских веб-новелл (zh → ru) с использованием LLM и человеческими контрольными точками на каждом этапе.

> **Идея:** автоматизировать рутину перевода через OpenAI-совместимые LLM-серверы, но оставить ключевые решения за человеком — выбор промптов, проверку качества, финальную корректуру.

---

## Быстрый старт

Рекомендуемый способ установки — **виртуальное окружение (venv)**: он
одинаково работает на Windows, macOS и Linux.

```bash
# 1. Создать и активировать venv (Python 3.10+)
python3 -m venv .venv && source .venv/bin/activate   # Linux/macOS
# Windows: py -m venv .venv && .venv\Scripts\activate

# 2. Установить зависимости
pip install -r requirements.txt
#    requests и tqdm — обязательные; pyahocorasick — опционален
#    (есть regex-fallback); pytest — только для тестов

# 3. Запустить пульт
python3 run.py
```

Допустимая альтернатива без venv — системный Python (Debian/Ubuntu):

```bash
sudo apt install python3-requests python3-tqdm python3-ahocorasick python3-pytest
```

Пульт — веб-интерфейс (`web/`): выбираете раздел → проект → стадию
конвейера в браузере (сервер поднимается `run.py`).

> **Windows:** интерпретатора `python3` там нет — вместо него используйте
> `python …` или `py …` (это касается всех команд в этом документе).

## Конвейер перевода

Каждая книга проходит шесть стадий — от EPUB до готовых форматов:

```
EPUB/текст
   │
   ▼
┌─────────────────────────────────────────────────────┐
│ ① Разбор исходника (epub_to_chapters)              │
│    EPUB или папка с текстом → папки глав            │
│    Результат: chapters/00000_N_Заголовок/chapter.txt│
└──────────────────────────┬──────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────┐
│ ② NER-глоссарий (ner)                               │
│    Извлечение имён, терминов, локаций → ner.json    │
│    Затем — проверка глоссария LLM (ner_check):      │
│    этап 1 — весь список, этап 2 — по типам;         │
│    правки LLM → ner_report.md + ner_review.json;    │
│    статусы принять/отклонить правит человек,        │
│    применение — --apply (есть --auto-apply)         │
│    Результат: выверенный ner.json                    │
└──────────────────────────┬──────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────┐
│ ③ Конвейер LLM: перевод → редактура → полировка     │
│    translate  — сырой перевод с контекстом           │
│    redact     — замена терминов по глоссарию NER    │
│    polish     — стилистическая доработка             │
│    Результат: polished.txt в каждой папке глав      │
└──────────────────────────┬──────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────┐
│ ④ Проверка перевода (translate_check)               │
│    Сверка оригинала и перевода: длина, покрытие      │
│    Результат: отчёт в logs/                         │
└──────────────────────────┬──────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────┐
│ ⑤ Проверка перевода LLM (translate_check_llm)      │
│    Поиск LLM → review.json → применение             │
└──────────────────────────┬──────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────┐
│ ⑥ Компиляция + Wiki                                  │
│    clean_and_compile → TXT / EPUB / FB2              │
│    wiki → wiki.md → публикация на Rulate             │
└─────────────────────────────────────────────────────┘
```

### Стадии LLM-конвейера (этап ③)

Три прохода над каждой главой:

| Стадия | Что делает | Вход → Выход |
| --- | --- | --- |
| **Translate** | Переводит китайский текст с учётом контекста и NER-глоссария | `chapter.txt` → `translated.txt` |
| **Redact** | Заменяет имена и термины по глоссарию, проверяет консистентность | `translated_trace.json` → `redacted.txt` |
| **Polish** | Стилистическая шлифовка русского текста | `redacted.txt` → `polished.txt` |

## Интерфейс

### Web-интерфейс (`run.py`)

Интерфейс один — **web** (сервер + SPA, пакет `web/`;
контракт API — `web/README.md`). Вкладки: пульт (разделы и проекты),
файлы, NER, проверка (глоссарий LLM / сверка алгоритмическая / перевод
LLM), конфиги, промпты, заметки, логи, запуски стадий.

```
python3 run.py                 # web-сервер + открыть браузер
python3 run.py --no-open       # без автозапуска браузера
python3 web/main.py --help     # флаги сервера (host/port/auth/токен/лимиты)
```

(на Windows вместо `python3` — `python run.py` или `py run.py`)

**Первый запуск.** Если папки `projects/` нет, `run.py` создаёт её вместе с
разделами (ACTIVE/HOLD/DONE) и, если системного `projects/.env`
ещё нет, копирует туда шаблон `templates/.env.example` (единый файл
настроек LLM-сервера и самого web-сервера; `find_env_file` находит его
автоматически).

**Разделы проектов** (динамические):

- **ACTIVE** — текущие проекты в работе
- **HOLD** — приостановленные
- **DONE** — завершённые

Порядок и состав разделов хранятся в `projects/.sections.json`
(источник истины после первого запуска); легаси-папки вроде DONE_OPEN
со старых установок подхватываются как пользовательские разделы.
«Управление разделами» на пульте: создание, переименование (при
совпадении имени — проекты переносятся в существующий раздел), удаление
пустых (непустой раздел удалить нельзя — сначала перенесите/удалите
проекты).

**Создание проекта** — пункт «＋ Создать новый проект…» в списке проектов.
Мастер спрашивает по порядку:

1. раздел — по умолчанию **ACTIVE**;
2. английское имя — пробелы заменяются на `_`, запрещённые символы
   удаляются (итоговое имя папки показывается до создания);
3. русское название, автор, жанры через запятую — опционально, попадают
   в `source/metadata.yaml` (дата заполнения — день создания);
4. тип книги — подпапка `templates/` с промптами (`General` по умолчанию):
   её `prompts/` и `source/` копируются в проект без перезаписи.

**Управление проектом** (в web-интерфейсе; общая логика —
`core/projects.py`):

- перенос между разделами (при переносе из ACTIVE в DONE —
  подтверждение);
- переименование;
- дублирование (копия для альтернативного перевода);
- статистика (главы/артефакты/ner/wiki + путь к папке);
- удаление — только после ввода слова `УДАЛИТЬ`.

Разделы динамические: дефолтные ACTIVE/HOLD/DONE гарантированно
существуют; пользовательские разделы добавляются/переименовываются/
удаляются через «Управление разделами».

### Запуски стадий

В web-интерфейсе стадии запускаются карточками «Запуски» (вкладка
«Пульт»): каждая стадия — карточка с формой параметров и кнопкой
«Запустить»; прогресс идёт SSE-стримом (`/api/jobs/{id}/stream`), задачи
очередью JobManager (лимит параллельности — `WEB_JOBS_LIMIT`).
Ключи стадий — слаги (`epub`, `ner`, `ner_check`, `pipeline`,
`translate_check`, `translate_check_llm`, `compile`, `wiki`,
`batch_replace`);
реестр — `web/stages.py::STAGE_SPECS`.

### Прямой запуск скриптов

Каждую стадию можно запустить напрямую из командной строки (с `cwd` = папка проекта;
на Windows вместо `python3` — `python` или `py`):

```bash
cd projects/ACTIVE/MyNovel
python3 ../../../scripts/translate_check.py --preset 1
python3 ../../../scripts/clean_and_compile.py --mode txt --start 1 --end 50
python3 ../../../scripts/batch_replace.py --dry-run
```

(из `projects/ACTIVE/MyNovel` корень репо — `../../..`; web-интерфейс
подставляет пути сам. Интерактивные параметры задаются формами стадий
в web.)

Все скрипты-исполнители (`scripts/`) поддерживают `--help` для списка параметров.

### Проверка глоссария LLM (ner_check)

`scripts/ner_check.py` отправляет глоссарий из `ner.json` в LLM и получает
правки (без LLM на этапе применения). Рекомендуемый двухэтапный режим:
этап 1 — весь список (`--passes whole`), человек правит статусы, `--apply`;
этап 2 — каждый `type` отдельно уже по обновлённому глоссарию
(`--passes types`), правки дописываются в тот же файл, снова человек и
`--apply`. Записи идут по `count` по убыванию, батч режется только при
превышении бюджета `--batch_size` (СИМВОЛЫ, по умолчанию 196608 ≈ 65536
токенов). Модель стадии — `NER_CHECK_MODEL` (fallback — общая `MODEL`) в корневом
`.env` (подставляет web-слой; прямой запуск скрипта — та же схема).

Правки накапливаются в `ner_review.json`: каждая несёт «этап», «статус»
(«принять»/«отклонить») и флаг «применено». Человек правит статусы и
значения «new» прямо в файле; `--apply` применяет только принятые и ещё
не применённые, а `ner_changes.md` хранит лог всех применённых правок
с этапами. Старый формат (простой массив патчей) понимается автоматически.
Параметры прогона сохраняются в мете файла, и лаунчер подставляет их
значения по умолчанию на этапе 2; запрос типового этапа содержит пометку
не трогать термины, уже унифицированные на этапе 1.
`--auto-apply` — авто-режим без человека (`--passes all --auto-apply` идёт
последовательно: whole → применение → types по обновлённым данным).

```bash
cd projects/ACTIVE/MyNovel
python3 ../../../scripts/ner_check.py --passes whole      # этап 1 → ner_review.json
# человек правит статусы в ner_review.json
python3 ../../../scripts/ner_check.py --apply --dry-run   # предпросмотр правок
python3 ../../../scripts/ner_check.py --apply             # применить (бэкап ner.json.bak)
python3 ../../../scripts/ner_check.py --passes types      # этап 2 → тот же ner_review.json
```

Интерактив (выбор сервера, этапы, предпросмотр, подтверждение применения,
полный автомат) — в web-интерфейсе, стадия «Проверка глоссария (LLM)».

### Проверка перевода через LLM (translate_check_llm)

`scripts/translate_check_llm.py` (бывший `fix_errors.py`) ищет ошибки в
файлах глав (`--type polished|redacted`) через LLM и вместо генерации
fix-скрипта пишет человекочитаемый накопительный файл
`translate_check_llm_review.json`: глава, файл, фрагменты «old»/«new»,
тип ошибки, причина, статус «принять»/«отклонить» и флаг «применено».
Человек правит статусы прямо в файле, затем `--apply` применяет только
принятые правки (бэкап `<файл>.bak` у каждой изменённой главы, лог
применённых правок — `translate_check_llm_changes.md`);
`--apply --dry-run` — предпросмотр без изменений. `--auto-apply` —
авто-режим без человека (поиск → сразу применение). Двухпроходная
верификация находок — `--two_pass`; модель стадии —
`TRANSLATE_CHECK_LLM_MODEL` (fallback — общая `MODEL`) в корневом `.env`. Старый формат (простой JSON-массив правок) понимается
автоматически.

```bash
cd projects/ACTIVE/MyNovel
python3 ../../../scripts/translate_check_llm.py --start 1 --end 50  # поиск → review-файл
# человек правит статусы в translate_check_llm_review.json
python3 ../../../scripts/translate_check_llm.py --apply --dry-run                  # предпросмотр
python3 ../../../scripts/translate_check_llm.py --apply                            # применить принятые
```

Интерактив (поиск, применение, предпросмотр, полный автомат) — в
web-интерфейсе, стадия «Проверка перевода (LLM)»
(translate_check_llm); алгоритмическая сверка — «Проверка исходника
(алгоритм)» / translate_check.

### Массовые замены (batch_replace)

Скрипт `scripts/batch_replace.py` применяет к главам список замен из
внешнего файла правил — без LLM и без интерактива (интерактив — стадия
«Массовые замены» в web). Полезно для финальной чистки имён и терминов
в готовых главах.

```bash
cd projects/ACTIVE/MyNovel
python3 ../../../scripts/batch_replace.py --dry-run            # показать, что заменится
python3 ../../../scripts/batch_replace.py --type polished      # применить к polished
python3 ../../../scripts/batch_replace.py --type chapter --start 1 --end 20
```

Файл правил по умолчанию — `prompts/replacements.txt` (лежит в папке
промптов проекта, рядом с промптами стадий). Шаблон с инструкцией и
готовыми примерами — `templates/replacements.txt.example`:
скопируйте его в `prompts/replacements.txt` и отредактируйте под свою
книгу (в примерах показаны замены имён, склонения через regex и
секции-заголовки). Формат: одна замена на строку `ЧТО -> НА ЧТО`; по
умолчанию — точный поиск подстроки, флаги `|i` (регистр) и `|r` (regex,
с обратными ссылками `\1…\9`) — в конце строки; строки `## …` — секции
для отчёта.

### Компиляция в EPUB / FB2

Скрипт `scripts/clean_and_compile.py` собирает главы в TXT, EPUB или FB2.
EPUB и FB2 генерируются нативно (stdlib, без внешних зависимостей).

**Обложка и метаданные.** В EPUB/FB2 встраиваются, если файлы найдены:

- обложка — `source/cover.jpg` (пути переопределяются `--epub-cover` /
  `--fb2-cover`; FB2 можно собрать без обложки: `--no-fb2-cover`);
- метаданные книги — `source/metadata.yaml` (`--epub-meta`): название,
  автор, описание, жанры, язык и т.п. Шаблон —
  `templates/General/source/metadata.yaml`.

Если обложки или метаданных нет — компиляция проходит без них.

**Страница поддержки (donate).** В конец EPUB/FB2 можно добавить страницу
«Поддержать проект». Для этого нужен файл с текстом:

1. Положить `source/donate.txt` (или `prompts/donate.txt`) в папку проекта.
2. Или передать путь через `--donate-file`.
3. Если файла нет — страница НЕ добавляется (встроенный текст отсутствует).

Шаблон: `templates/donate.txt.example` — скопируйте в проект
и отредактируйте под себя.

## Конфигурация LLM-сервера

Системный `.env` (projects/.env) задаёт подключение к LLM и настройки
web-сервера; проектный `pdir/.env` приоритетнее для конкретной книги.
Приоритет: CLI-флаг > окружение > `.env` > дефолт. Редактировать можно
во вкладке «Настройки» web-интерфейса.

**Настройки запусков (R9).** Поля форм «Запусков» предзаполняются из
`.env` и при каждом запуске сохраняются обратно: системный
`projects/.env` копируется в папку проекта (`pdir/.env`), если её нет,
затем обновляются ключи `<STAGE>_<FIELD>` (например `NER_CHUNK_SIZE`,
`TRANSLATE_CHECK_EXCLUDE_WORDS`; модель — `<STAGE>_MODEL`, fallback —
общая `MODEL`). Проектный `pdir/.env` приоритетнее системного.
`API_KEY` не сохраняется (только предзаполнение формы); системные
`WEB_*` (настройки web-сервера) в проект не копируются. Слова-исключения проверки перевода —
`TRANSLATE_CHECK_EXCLUDE_WORDS` (дефолт `VIP,MVP,【,】,NPC`).

```ini

```ini
# Единый сервер LLM (vLLM, Ollama, LM Studio, OpenAI-совместимый)
HOST=http://localhost:8080/v1
API_KEY=your-api-key
MODEL=gemma-3-novel-224b

# Модель конкретного скрипта (необязательно; fallback на общую MODEL)
NER_MODEL=...
NER_CHECK_MODEL=...
TRANSLATE_CHECK_LLM_MODEL=...
WIKI_MODEL=...
PIPELINE_MODEL=...   # web-конвейер (единая модель)
```

**Приоритет модели:** `<СКРИПТ>_MODEL` → общая `MODEL`. Правило — один
скрипт, один набор «сервер + ключ + модель»: отдельных моделей под
перевод/редактуру/полировку в конвейере больше нет (убраны
`TRANSLATE_MODEL`/`REDACT_MODEL`/`POLISH_MODEL`). Модель обязательна:
берётся из `--model` или `.env`, автоопределение через `GET /models`
убрано.

> Модели скриптов (`NER_MODEL`, `NER_CHECK_MODEL`,
> `TRANSLATE_CHECK_LLM_MODEL`, `WIKI_MODEL`, `PIPELINE_MODEL` и т.п.)
> подставляет web-слой (`web/stages.py`); при прямом запуске
> `scripts/*.py` — та же схема.

Web-сервер читает из того же `.env` ключи `WEB_HOST`, `WEB_PORT`,
`WEB_AUTH`, `WEB_TOKEN`, `WEB_MAX_UPLOAD_MB`, `WEB_JOBS_LIMIT`
(см. `templates/.env.example`).

**Приоритет конфигурации:** аргументы CLI (`--host`, `--model`, `--api_key`) → `HOST`/`API_KEY`/`MODEL` из `.env` → встроенный fallback → подсказка и ручной ввод.

Без `.env` скрипт не упадёт — предложит ввести параметры вручную и покажет подсказку по формату файла.

> 🔒 **Важно:** файлы `.env` содержат API-ключи и не коммитятся в git. Шаблон — `templates/.env.example`.

## Промпты

Промпты стадий лежат в папке `prompts/` проекта. Два допустимых способа
хранения:

1. **Отдельный файл на стадию** (рекомендуемый; так разложены шаблоны в
   `templates/General/prompts/`): файл целиком = промпт стадии, теги не
   нужны.
2. **Несколько стадий в одном файле**: промпт каждой стадии обёрнут в теги
   `<имя_стадии>…</имя_стадии>`; файл без нужного тега трактуется целиком
   (как в способе 1), а встроенный промпт — только когда файла нет.

Имена файлов и теги по стадиям:

| Стадия | Файл (по умолчанию) | Теги (в режиме общего файла) |
| --- | --- | --- |
| Перевод | `prompts/translate_prompt.txt` | `<translate>` |
| Редактура (redact) | `prompts/redact_prompt.txt` | `<redact>` |
| Полировка (polish) | `prompts/polish_prompt.txt` | `<polish>` |
| NER-извлечение | `prompts/ner_prompt.txt` | `<prompt_pass1>`, `<prompt_pass2>` |
| Проверка глоссария (ner_check) | `prompts/ner_check_prompt.txt` | — (файл целиком) |
| Проверка перевода (LLM) | `prompts/translate_check_prompt.txt` | `<pass1>`, `<pass2>` |
| Wiki-статьи | `prompts/wiki.txt` | `<prompt_wiki_article>` |

Плейсхолдеры внутри промптов (подставляются скриптом автоматически):

| Плейсхолдер | Где подставляется |
| --- | --- |
| `{ner_block}` | translate / redact / polish |
| `{original_text}` | redact |
| `{translated_text}` | redact |
| `{female_names}`, `{male_names}` | translate / redact / polish (основное назначение — polish: имена из ner.json по полю `translation`, пол по наличию `(female)`/`(male)` в `type`) |

В translate и polish текст главы добавляется после промпта автоматически
(без плейсхолдера); в redact оригинал и черновик подставляются через
`{original_text}` и `{translated_text}`. Для
`translate_check_prompt.txt` без тегов `<pass1>/<pass2>` используются
встроенные промпты скрипта.

## Шаблоны проектов

Каталог `templates/` содержит стартовые файлы для новых проектов. Общие
шаблоны лежат в корне каталога; подпапки — наборы промптов и файлов под
конкретный тип книги (жанр и язык).

| Файл | Назначение | Куда копировать в проекте |
| --- | --- | --- |
| `templates/.env.example` | Единый конфиг: LLM-сервер + WEB_* | `projects/.env` (системный) |
| `templates/donate.txt.example` | Страница «Поддержать проект» | `source/donate.txt` |
| `templates/replacements.txt.example` | Шаблон правил массовых замен | `prompts/replacements.txt` |
| `templates/General/prompts/*_prompt.txt` | Стартовые промпты NER/ner_check/перевода/редактуры/полировки | `prompts/` (имена файлов сохраняются) |
| `templates/General/source/metadata.yaml` | Метаданные книги для EPUB/FB2 | `source/metadata.yaml` |

`General/` — универсальный тип книги (подходит для большинства новелл).
Под другие жанры и языки добавляются новые подпапки рядом с `General/`.

## Тесты

```bash
# Базовый запуск (на Windows вместо python3 — python / py)
python3 -m pytest tests/ -q

# С проверкой покрытия (нужен pytest-cov)
python3 -m pytest tests/ -q --cov=core --cov=scripts --cov=web
```

Тесты не требуют сети — LLM мокнут через monkeypatch, данные создаются во временных папках.

## Зависимости

Рекомендуемый способ установки — **venv** + `pip install -r requirements.txt`
(см. Быстрый старт): работает на Windows, macOS и Linux. Альтернатива —
системный Python и пакеты `python3-*` через apt (Debian/Ubuntu).

| Пакет (pip / apt) | Назначение | Обязательность |
| --- | --- | --- |
| `requests` / `python3-requests` | HTTP-запросы к LLM | обязательный |
| `tqdm` / `python3-tqdm` | прогресс-бары | обязательный |
| `pyahocorasick` / `python3-ahocorasick` | быстрый поиск терминов | опциональный (regex-fallback) |
| `pytest` / `python3-pytest` | тесты | только для разработки |
