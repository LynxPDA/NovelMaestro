# web — web-интерфейс

Статус: **работает** (v1.0 M1–M8 + v2 W1–W9, web-first). Единственный интерфейс проекта: тот же конвейер перевода (`cli/` + `core/`), управление — через браузер (cli/tui удалены).

## Запуск

```bash
python3 run.py                  # web-сервер + открыть браузер
python3 web/main.py             # 127.0.0.1:8756, без токена (локально)
python3 web/main.py --host 0.0.0.0 --auth   # доступ с LAN + токен
```

По умолчанию сервер слушает `127.0.0.1` — только этот компьютер (`http://127.0.0.1:8756`), аутентификация **выключена** (локальный доступ безопасен). Для доступа с других машин локальной сети — `--host 0.0.0.0` (`http://<LAN-IP>:8756`) и **обязательно** включите токен: `--auth` или `WEB_AUTH=1` — тогда вход по токену (`--token` > `.web_secret`, автогенерация, chmod 600), а секреты `.env` в браузер отдаются маской: точка на каждый символ значения.

Параметры: `--host --port --auth --token --open --max-upload-mb --jobs-limit --projects-dir`; источник: CLI-флаг > окружение > корневой `.env` (`WEB_HOST WEB_PORT WEB_AUTH WEB_TOKEN WEB_MAX_UPLOAD_MB WEB_JOBS_LIMIT WEB_PROJECTS_DIR`) > дефолт. `--projects-dir`/`WEB_PROJECTS_DIR` — папка проектов (по умолчанию `<репо>/projects`; там же `projects/.web_secret` и `projects/.sections.json`). `--no-auth` — устаревший no-op.

Порт занят (другая копия сервера) — `main.py` автоматически берёт следующий свободный (`port+1 … port+100`) и пишет фактический адрес в консоль и в баннер; браузер открывается на реальном адресе.

## Возможности

- **Дашборд**: сводка одним запросом — все проекты со статистикой, последние запуски, «Продолжить» по последнему проекту.
- **Проекты (hub)**: разделы ACTIVE/HOLD/DONE (динамические: создание/переименование с merge/удаление пустых через «Управление разделами»; `projects/.sections.json` — источник истины), карточки проектов, создание/перенос/переименование/копирование/удаление (с подтверждением); мастер создания — опциональные загрузка обложки (jpg/png → `source/cover.*`, `PUT /api/cover`) и исходника (txt/md/epub/zip → `source/`, `POST /api/upload` с dest=source), реестр стадий `web/stages.py::STAGE_SPECS` (ключи-слаги), дерево глав с артефактами, шаблоны проектов.
- **Файлы**: браузер/редактор/загрузка (multipart, свой парсер)/скачивание, песочница `resolve_path` (запрет `..`, абсолютных путей, симлинк-побега); строка списка — чекбокс выделения, имя, метаданные и кнопки ОДНОГО объекта (файл — «править», «скачать» и «переименовать», каталог — только «переименовать»); групповые действия живут в панели выделения, и пока выделка есть она заменяет кнопки тулбара («Загрузить», «＋ Файл», «＋ Каталог»): «выделено: N», «переименовать» (только при одном объекте), «скачать» (файлы выделки), «перенести в…» (один вызов на всю выделку, выбор папки по дереву `dirs`), «удалить» (каталоги — вместе с содержимым) и «снять выделение»; «выделить всё» — первой колонкой тулбара над чекбоксами строк; все действия — SVG-иконки (`UICore.icon`) с подписью в тултипе и `aria-label`, построчных меню «⋮» больше нет; время изменения — относительно («3 ч назад»), точное — в подсказке; большие файлы (>5 МБ) не открываются в редакторе (413, скачивание).
- **Редактор**: CodeMirror 6 (вендор в `static/vendor/`, офлайн): вкладка «Редактор» — главы проекта (артефакты по маскам: канон И легаси `*_перевод/редактура/полировка`), панели Оригинал/Перевод/Редактура/Полировка — по умолчанию два файла: слева оригинал, справа полировка > редактура > перевод (по доступности); канонические файлы видны, даже если их ещё нет — пустой редактор, сохранение создаст файл (напр. polished.txt до полировки); сохранение через `/api/file`; подсветка терминов глоссария оверлеем (по умолчанию вкл; поиск по логике `translate_book.py`: `normalize_for_search` + точное вхождение со слово-границами + нечёткие n-граммы «корень+окончание», поле «n-грамма» — аналог `--ner_ngram`, дефолт 3, и поле «Порог» — аналог `--ner_threshold`, дефолт 0.75, выше — строже; порог применяется сразу при вводе), тултип с «→ Глоссарий»; выделение в `chapter.txt` — «＋ в глоссарий» (форма: термин, тип, перевод; `context` ≤200 символов, `count=1`; дубль — предупреждение); DOM вкладки кешируется, пока открыт проект (возврат из «Глоссарий» без сброса); F5 больше не сброс: глава, обе панели, режим и подсветка берутся из состояния книги (`nmTab:<раздел>/<книга>`, `UICore.projectPrefs`); настройки — localStorage браузера, не .env. подсветка по расширению файла (md/html/json/yaml/py; промпты — язык «prompt», теги и плейсхолдеры видны), без ручного выбора представления; у панели кнопки «Редактор»/«Предпросмотр» (режим — по расширению, у текста без разметки предпросмотр показывает тот же текст с сохранением переносов, md/html — sandbox-iframe); поиск/замена — Ctrl+F/Ctrl+H или кнопка с лупой в заголовке панели (у многосоставной панели — в шапке активной); fallback на textarea.
- **NER**: таблица глоссария — инлайн-редактирование строк, настраиваемые столбцы (все поля ner.json, настройка в localStorage), сортировка кликом по заголовку (первый — убывание, повтор — возрастание; по умолчанию `count` по убыванию, даже если столбец скрыт; порядок — в состоянии книги), добавление/удаление, поиск слева (поле + выбор полей), справа — кнопки типов и столбцов; выбор столбцов/полей/типов — единая модалка «Все / набор» (всё снять нельзя — остаётся первый пункт, «Все» сверху; подписи кнопок «Все поля/типы/столбцы» → «Поля/Типы/Столбцы (N)»); тултипы на всех кнопках; review-флоу: `tmp/ner_review.json` / `tmp/translate_check_llm_review.json`.
- **Проверка**: отчёты translate_check (`logs/check_*.txt`) — таблица «глава → папка → ошибки» с переходом в «Файлы», FATAL подсвечен; LLM-карточки (`tmp/ner_review.json` / `tmp/translate_check_llm_review.json`) — переключатель «Список правок / Редактор JSON»: список отдельных правок со сводкой (всего/принято/отклонено/применено), кнопки «Принять», «Отклонить», «Откорректировать» (Было/Стало/Причина — JSON: old/new/reason) и переход к тексту правки; действие правки — `action`: «патч» поля или «удаление» термина (LLM помечает термин лишним: у такой записи поле пустое, `old` — текущие значения, в списке она идёт с красной чертой и подписью «удаление термина», в модалке — «Что уходит» без поля «Стало», на применённом accept запись вычёркивается из ner.json со всеми дублями) («→ Глава» — файл главы с поиском фрагмента, «→ Глоссарий» — таб с поиском термина); неприменённые правки с причиной пропуска видны в карточке (поле `note`: цитата не найдена в книге / найдена в нескольких главах — не однозначно / файл главы не найден); пропущенные правки с уникальной цитатой автоматически перепривязываются к реальной главе (дрейф атрибуции LLM ±1: цитата ищется по всей книге, применение — только при ровно одном совпадении ровно в одной главе); JSON-редактор — прежний режим. Применение запускается как фоновая задача и уведомляет о завершении toast-ом (✅/❌/⏹); перед применением — контрольная точка истории (вкладка «История»).
- **Настройки**: редактор `.env` в web ОДИН — общий файл `WEB_ENV_FILE` (в Docker — `projects/.env` в томе), иначе корневой `.env` репо; `env_wins` — ключи, заданные переменными процесса: они перекрывают файл, и правка в интерфейсе их не применит, пока не убрано окружение. Страница рендерит реестр (`core/settings.py`) пятью субвкладками (Модель и сервер, Перевод, Глоссарий, Проверки, Книга и файлы); внутри — карточки блоков, в них — поля реестра с метками, типами, вариантами и подсказками; значения видимы без auth, секреты (`API_KEY`, `WEB_TOKEN`) отдаются маской (точка на символ значения — четыре точки на 20-символьный ключ выглядели обрезанным вводом) и без правки обратно не пишутся. Настройки самого сервера (`server_net`, `server_run`) из интерфейса убраны: в реестре они остаются (их же читает `web_values()`), просто `groups_payload()` их не выводит — адрес, порт и токены сервера задаются флагами запуска и в карточках книги не нужны. Путь файла интерфейсу тоже не показывается: это реализация, а не настройка. У блока может быть `note` — ОДНА строка «что это и когда трогать» (карточка настроек не должна становиться справочником: детали — во вкладке «Справка»); так появился и поясняющий текст у «Выбора провайдера»: карточка касается только роутеров (RouterAI, OpenRouter), локальный сервер её не читает, а списки идентификаторов разделяются запятой, «;» или пробелом. Чекбоксы реестра — такое же двухстрочное поле, как соседи (подпись сверху, контрол и состояние «включено/выключено» строкой под ней): строкой они висели по центру колонки и съезжали относительно полей. В карточке «Подключение» — кнопка «Проверить сервер»: один короткий GET /models по значениям ФОРМЫ (сервер не сохраняется), вердикт одной строкой — жив/не отвечает, время, число моделей и есть ли в списке модель из конфига; это отдельный цвет `.settings-check-state.is-ok|is-warn|is-bad`, а не ошибка страницы. Шестая субвкладка — локальная «Внешний вид»: тема и кегль редакторов, кегль предпросмотра и ЯЗЫК подсветки (два select: промпты и логи — у тех и других расширение не подсказывает язык) — всё localStorage браузера, без полей реестра и без «Сохранить». Собственного `.env` у книги нет вовсе (легаси-копии вынесены в `backup/legacy_book_env/`), во «Файлах» старый `.env` книги остаётся обычным файлом. Внешний вид — localStorage браузера (не .env): тема интерфейса — переключатель в шапке (`UICore.toggleUiTheme`), остальное — субвкладка «Внешний вид». Вкладка проекта «Настройки» (бывш. «Конфиг») — только данные книги: «Обложка» (upload/предпросмотр/удаление, `source/cover.*`), «Метаданные epub/fb2» и «Файл страницы поддержки» — выбор файла из `source/` + редактор; дефолты обложки/метаданных/доната задаются в форме стадии compile (`COMPILE_COVER`/`COMPILE_EPUB_META`/`COMPILE_DONATE_FILE` в общем `.env`).
- **Промпты**: файлы `prompts/` + шаблоны `templates/*/prompts` в одном списке; создание промпта из шаблона.
- **Запуски**: все стадии пайплайна, ФОРМА ОДНА на стадию — переключатель «Простой/Экспертный», карточки-пресеты и `spec.simple`/`preset` удалены: поля берутся из реестра (`spec.fields` = `core/settings.form_fields(stage)`), порядок — порядок реестра, диапазон глав — одной строкой «Главы: start – end» первым полем. Поля режима стадии описаны у самой настройки (`when`/`when_any`/`when_set` в реестре): их не прячет и не выключает ни SPA, ни сборка — `core/settings.applicable_form(stage,form)` фильтрует форму перед `build_*`, а SPA перекрашивает вид через `UICore.fieldApplies` (обёртки-виджеты — чипсы, предпросмотр — следуют за своим полем-владельцем). Пустой режим поля не режет; значения неприменимых полей остаются в браузере к следующему запуску. LLM-полей (host/model/api_key/temperature/потоки) в форме запусков НЕТ: единые значения подставляет сервер (`core/settings.with_llm()`), что бы ни лежало в старом кэше браузера или старом `.env` книги. Значения формы (`st.values`) — рабочее состояние браузера: предзаполнение из эффективного конфига плюс автоподхваты (диапазон глав, prompt_file, autofile); эталон сброса — значения сразу после инициализации (`st.baseline`), а не пустые дефолты спеки. «Сбросить настройки (N)» в шапке панели возвращает поля к эталону (на диске писать нечего); узел кнопки ПОСТОЯНЕН и прячется классом `hidden` — пересоздавать нельзя: `change` предыдущего поля приходит между mousedown и mouseup, старый узел отрывается и клик уходит в родителя. Выбор чипсов (hidden-поля `noenv`) — localStorage по проекту+стадии (`chipKey`); `st.touched` по-прежнему нужен чипсовым виджетам. Многострочные regexp-поля (epub паттерны разбивки, regexp-проверки translate_check, правила batch_replace): комментарий в конце строки — « # …»; в `.env` хранятся одной строкой с переносами как «\\n» (`EPUB_SPLIT_PATTERNS`, `TRANSLATE_CHECK_REGEXP_CHECKS`, `BATCH_REPLACE_REPLACEMENTS`). live-лог + SSE (reconnect с backoff при обрыве), прогрессбар LLM-стадий (события `@@PROGRESS@@` из скриптов, `WEB_PROGRESS=1` ставит JobManager.start в env subprocess, tqdm в web отключается; без событий бар скрыт) с оценкой времени завершения — ETA по скользящему окну событий (шаг ≥5 c, окно 15 точек) с фолбэком от старта запуска, пока событий мало; конвейер с таблицей глав (✓/✗/⊘, строки — реальные главы из `options.chapters.ids`), stop — остановка **вместе с потомками** (POSIX: сигнал группе процессов, SIGTERM → 5 с → SIGKILL; Windows: tree-kill `taskkill /F /T` — групп процессов/сигналов там нет, а terminate() бьёт лишь по родителю — дочерние translate_book.py осиротели бы и держали унаследованный stdout-пайп). «Запуски» — вкладка проекта (роут `#/project/{s}/{n}/run`, короткий `#/run/{s}/{n}` — тот же вид; `#/run/{s}/{n}/{jobId}` и «Показать» на карточке — `…/run/{jobId}`). Истории НЕ показывает: слева — карточка **активного** запуска проекта (badge/бар/переход/стоп), лог (текстовое окно + SSE) — только у активного запуска; завершённый запуск по URL `…/run/{jobId}` лог не открывает (история логов — во вкладке «Логи» проекта). Таблица конвейера — события текущего запуска + фактическое состояние артефактов глав (статус проекта), так что галочки видны и для ранее переведённых глав. Метаданные всех запусков — `web/job_logs/jobs.json` (внутри `job_logs/`, чтобы в docker переживать пересоздание контейнера — volume), хвост лога/событий — `web/job_logs/{id}.log` (переживает рестарт сервера). При move/rename проекта журнал следует за проектом: project/cwd у его записей переписываются (`JobManager.update_project_path`), иначе логи стадии после переноса в другой раздел «пропадали бы».
- **Дашборд**: «Последние запуски» — до 20 записей (`MAX_HISTORY=20`), колонки Задача/Проект/Статус/Прогресс/Дата; клик по строке ведёт на вкладку «Запуски» проекта (без job id); кнопка «Очистить» (DELETE `/api/jobs`) удаляет завершённые запуски, активные остаются. Активные запуски собираются из ПОЛНОГО списка jobs, а не из среза «последних 20».
- **Промпты конвейера**: форма pipeline — единый «Общий промпт-файл» с тегами `<translate>/<redact>/<polish>` (режим промптов и отдельные файлы на стадию убраны). Пусто = auto: первый кандидат с тегами из `prompts/` (`pipeline_prompt.txt` → `prompts.txt` → `translate_book_prompt.txt`), иначе стадии используют встроенные промпты. Если в общем файле нет тега стадии — предупреждение в логе запуска, стадия уходит на встроенный промпт (то же в translate_book.py, ner.py `<prompt_pass1>/<prompt_pass2>`, translate_check_llm.py `<pass1>/<pass2>`, ner_check.py `<prompt_ner_check>/<prompt_rag>`, wiki.py `<prompt_wiki_article>` + JSON-теги). Теги достаются единым `get_tagged_prompt` (открывающий тег — только в начале строки: упоминания в «#»-комментариях не захватываются). Файл без тегов = промпт стадии целиком (легальный режим). Автоподхват — только реально существующие файлы: удалённый промпт не остаётся выбранным (ни из .env-памяти, ни в форме); «Общий промпт-файл» предзаполняется победителем auto-режима (`options.auto_prompt`). Кэш опций инвалидируется по max mtime файлов папки — перезапись промпта тоже обновляет списки.
- **Перевод с расширенным контекстом** (действие 9, малоресурсные языки): словарь/правила/примеры из `source/` через «Файлы»: `dict.json` — словарь в формате ner.json (term/translation/type?/ aliases?/notes?), ищется как глоссарий по чанку + сторонам выбранных примеров → `{dict_block}` (JSON); `rules.txt|md` — справочник языка, целиком в `{rules_block}` (общий потолок — `--request_budget` ТОКЕНЫ, оценка); `examples.json` — пары `{original_text, translated_text}` (алиасы source/target; совместим с `translated_trace.json`), релевантные чанку пары — few-shot `{fewshot_block}` (JSON; containment n-грамм по ОБЕИМ сторонам пары — автодетект направления перевода, топ-K со штрафом за пересечение, порог `fewshot_threshold` — лучше без примеров, чем с шумными; словарь — та же автодетект-логика: совпадения по term и translation, где больше — та сторона). Плейсхолдеры заменяются во всех стадиях (нет файла — «(нет)»); промпт перевода — тег `<translate_lr>` (фолбэк `<translate>` → встроенный); `--request_budget` — общий бюджет user-запроса, ТОКЕНЫ (оценка estimate_tokens; превышение — ошибка чанка); предпросмотр запроса учитывает блоки.
- **Глоссарий — всегда ner.json**: по архитектуре проекта чтение и сохранение глоссария во всех стадиях — файл `ner.json` в корне проекта (выбор файла в формах убран). Review-файлы правок — тоже без выбора: `tmp/ner_review.json` и `tmp/translate_check_llm_review.json` (их же читают вкладки «Правки»). Форма ner без режима: `ner.json` отсутствует — создаётся новый, существует — дообучение; вход — всегда сборка глав из диапазона. Таймаут в формах — один («Таймаут, сек»); скриптам с раздельными таймаутами (`--stream_timeout`) значение передаётся тем же числом.
- **Профили LLM (поле в форме стадии)**: первое поле формы каждой LLM-стадии — «Профиль LLM» (у стадии без модели его нет), подпись под ним сразу показывает выбранное: «General — значения общего конфига (…)» / «Дачный — наследует General (сервер, модель, рассуждения: on)». Выбор — свой у каждой стадии проекта, живёт в localStorage `nmProfile:<раздел>/<книга>:<стадия>` и приезжает на сервер вместе с `params`. `with_llm()` разбирает профиль по историческим именам полей стадии, поэтому своих LLM-полей (host/model/api_key/потоки) в форме нет и `spec.fields` их не содержит. Смена профиля не считается «изменённой настройкой»: кнопка «Сбросить настройки» его не трогает.
- **Рассуждения модели — ОДИН режим на весь конвейер** (не на стадию): карточка «Рассуждения модели» на странице «Настройки» пишет общие ключи общего `.env` (`REASONING_MODE` / `THINKING_PROFILE` / `REASONING_EFFORT` / `THINKING_BUDGET`, пустой уровень и нулевой бюджет — не отправлять); стадии читают их сами, в argv запуска ничего не прокидывается. Спеки стадий reasoning-полей НЕ содержат: шесть одинаковых полей разъехались бы по значениям в одном запуске (модель-то одна). Реестр профилей провайдеров — `core/common.py::REASONING_PROFILES` (openai/anthropic/qwen/dashscope/ollama/openrouter/all); каждый профиль отправляет только свои ключи.
- **Настройки запусков** (R9): `GET /api/stages/{key}/spec?project=…` отдаёт спеку, поля и значения которой собраны из реестра (реестр → общий `.env` → профиль стадии → `os.environ`); `options` — списки файлов/глав. Поле `profile` в спеке перечитывается при каждом открытии формы (профиль могли создать вне интерфейса), его варианты — id профилей, подписи — их имена. Ни `overridden`, ни стадийных LLM-ключей в спеке нет: книга больше не хранит свой конфиг, изменённые для неё поля — состояние браузера. `POST`-а «сбросить отличия» тоже нет: сброс (`st.baseline` → `st.values`) ничего не пишет на диск и обновляет форму на месте.
- **Заметки**: `GET/PUT /api/notes` — `projects/notes.md` (markdown-редактор на вкладке «Заметки», рендер в sandbox-iframe).
- **Справка**: вкладка в левой панели — `static/help.md` (markdown), рендер `marked` + TOC по h2/h3 (липкий список разделов); контент: программа, проекты, вкладки проекта, шаблоны, запуски, regexp.
- **Логи**: список `logs/` и `logs/chapters/`, хвост, follow.

## Стадии (порядок в «Запусках»)

Порядок карточек стадий задаёт `web/stages.py::STAGE_ORDER` (логика конвейера: разбор → NER → проверка глоссария → конвейер → проверка → правки → замены → компиляция → вики). Название стадии берётся из ОДНОГО места — `core/settings.py::STAGE_TITLES`: карточка «Настроек» и запуск называются одинаково (раньше у одной стадии было два имени — «Глоссарий (NER)» в настройках и «Создание глоссария (LLM)» в запусках). Слаги — контракт API, не менять. Имя скрипта — подпись карточки в UI и колонка `script` в `/api/stages`.

| Слаг | Название в UI | Скрипт | LLM |
| --- | --- | --- | --- |
| `epub` | Разбор исходника на главы | `cli/epub_to_chapters.py` | нет |
| `ner` | Создание глоссария (LLM) | `cli/ner.py` | да |
| `ner_check` | Проверка глоссария (LLM) | `cli/ner_check.py` | да |
| `pipeline` | Перевод (LLM) | `web/pipeline.py` | да |
| `translate_check` | Проверка перевода | `cli/translate_check.py` | нет |
| `translate_check_llm` | Проверка перевода (LLM) | `cli/translate_check_llm.py` | да |
| `batch_replace` | Массовые замены | `cli/batch_replace.py` | нет |
| `translate_quality` | Оценка перевода (LLM) | `cli/translate_quality.py` | да |
| `compile` | Компиляция TXT/EPUB/FB2 | `cli/clean_and_compile.py` | нет |
| `wiki` | Создание Wiki (LLM) | `cli/wiki.py` | да |

Стадия `ner` — 3 режима формы: `extract` («Новый глоссарий (автоматический)»), `finetune` («Дообучение»), `postprocess` (обработка ner.json без LLM: `strip_meta`/`min_count`; LLM-поля формы скрываются). Режим «Собрать главы + извлечение» убран: extract/finetune без входного файла сами склеивают главы `chapters/*/chapter.txt` в память (`--compile_chapters`, без временного файла); поля `start`/`end` — диапазон глав (ГЛАВЫ), видны только когда файл не выбран. Файл в CLI — позиционный аргумент. Все текстовые поля, в голосование не попавшие (`notes`, `context`, `translated_context`), получают ОДНО значение по одному `NER_NON_VOTED_MODE` (`last` — как исторически, `first`, `longest`, `shortest`): режим больше не различает поля, он выбирает значение для всех неголосующих текстовых полей записи; для «самого длинного» есть потолок длины `NER_NON_VOTED_MAX_LEN` (СИМВОЛЫ, 0 — без ограничения). Любое из этих полей можно вернуть в голосование `NER_KEEP_FIELDS`.

Стадия `ner_check` — «Режимы» одним select: «Выбранные типы (одновременно)» (`whole`, по умолчанию) и «Выбранные типы (по очереди)» (`types`); режим «Полный цикл» убран. Карточки-пресеты убраны (дублировали select), типы — только чипсы-чекбоксы из глоссария (поле «Типы через запятую» удалено). В режиме `rag` — поля RAG: список терминов, тип исходника и бюджет на термин (`rag_budget`, ТОКЕНЫ). Review-файл пишется после КАЖДОГО батча/термина (дифф и сохранение прямо при приёме результата — упавший прогон не теряет правки готовых батчей); настроек интервала сохранения и чанка FTS5 нет.

Стадия `translate_quality` — оценка качества одним LLM-запросом или чанками всей книги; режим `mode` select: «Диапазон одним запросом» (`range`, по умолчанию) и «Чанками всей книги» (`chunks`). Собираются `{original_text}` (chapter.txt) и `{translated_text}` (поле `type`, «Тип файлов глав») и подставляются в промпт (тег `<prompt_assessment>`, `prompts/translate_quality_prompt.txt`). `budget` — ТОКЕНЫ (оценка; содержимое глав, промпт не вычитается); в режиме `range` не влезает — пакет обрезается до ЦЕЛОГО количества глав (первые N диапазона), отсечённые указываются в отчёте.

Стадия `translate_quality`, режим `chunks`: книга режется на чанки по `chunk_size` ЦЕЛЫХ глав (`overlap` — сколько соседних глав входит в оба чанка), оценивается `chunks` чанков (`0` — все) с отбором `sample` («равномерно по книге» / «первые по порядку»), запросы идут потоками общего `THREADS`. Глава крупнее бюджета режется по абзацам (`split_text_smart`, hard_limit = бюджет) и становится несколькими чанками одной главы; часть перевода едет в запрос со своим куском оригинала; глава, которая не режется, остаётся в строке «больше бюджета». Отчёты чанков сворачиваются LLM в заключение тем же `budget`: батчи ≤ бюджета → промежуточные сводки, снова батчи (`MAX_REDUCE_LEVELS` = 3 уровня), сжатие каскадом (полные отчёты → без цитат → только баллы), не сошлось — текст урезается, в отчёте помечено. Артефакты — `tmp/quality/` (`chunk-NNN.json`, `summary-l<k>-<i>.json`); новый запуск каталог затирает, `--summary-only` перечитывает его и сводит без запросов по чанкам. Шкала 0–10 и названия разделов оценки живут только в промпте, код их не задаёт. Выход — `tmp/translation_quality_assessment.md` (в web имя фиксировано, поле «Выходной файл» убрано; в CLI переопределяется `--output`): техническая шапка, сводка баллами (среднее, медиана, минимум, максимум, разделы), merged замечания и похвалы, «Чанки с ошибками», заключение LLM и приложение по чанкам. На вкладке «Проверки» секция «Оценка перевода (LLM)» рендерит этот отчёт (без выбора файла).

Стадия `compile`: режимы `txt` («TXT (Rulate)»), `txt-plain` («TXT»), `epub`, `fb2`; поле «Глав в части» (`chunk_size`) работает для любого режима: >0 — диапазон разбивается на части по столько глав, пусто/0 — одна сборка. Финальные файлы сборки пишутся в КОРЕНЬ проекта (`--out-dir`) с названием проекта в имени: `{Имя}_{начало}_{конец}_txt.txt` / `.epub` / `.fb2`; рабочие файлы (titles) — в `tmp/`, промежуточный txt для epub/fb2 не создаётся (книга собирается из памяти). TXT (Rulate) оформляет заголовки глав под Rulate (`# [Глава N :|: N]`), TXT — обычные markdown-заголовки без тегов. Единое поле `cover` (files из `source/`, jpg/jpeg/png/webp/gif/bmp) — обложка для EPUB и FB2 одновременно (`--epub-cover` + `--fb2-cover`); пусто = `--no-cover` (автоподхват `cover.*` отключён). `epub_meta` (files из `source/`, yaml/yml) — метаданные; пусто = авто `metadata.yaml`. `donate_file` (files из `source/`, txt) — страница поддержки; пусто = `--no-donate` (автоподхват `source/donate.txt` отключён). Чекбоксы «Без страницы поддержки»/«Без обложки в FB2» убраны. В txt-режимах поля обложки/метаданных/доната скрыты. В форме — предпросмотр обложки/`metadata.yaml`/страницы поддержки. Ключи `.env`: `COMPILE_COVER`, `COMPILE_EPUB_META`, `COMPILE_DONATE_FILE`. Заголовок главы: первое «Глава N» в файле → иначе первая непустая строка («Пролог. Пример» → название) → иначе «Глава N».

Стадия `epub` — разбор исходника на главы (только `.epub`/`.txt`, ZIP не принимается): режимы `toc` (только epub, по структуре spine/TOC/h1-h2), `regex` (строки-маркеры `--split-re`, по одному на строку) и `chunk` (`--chunk-size` в ТОКЕНАХ (оценка) + маска `--chunk-mask` с `{num}`, дефолт «Chapter {num}»); epub в regex/chunk-режимах перегоняется в текст. Каталоги глав — канон `00000_1_…` (нули добивают ширину 6), `--title-limit` (СИМВОЛЫ, 50), `--num-offset`, `--skip` с перенумерацией; `--output-type` — какой файл создаётся в папке главы (`chapter`/`translated`/`redacted`/`polished`); `--rename-chapters` — переопределить названия ВСЕХ глав маской (`--chunk-mask`); `--replace-re` — regexp-замены «паттерн -> замена» (пустая правая часть — удаление), применяются ДО разбивки (нормализация маркеров глав); поле «Очистки текста» убрано из формы (регулярные замены и очистка — единое поле «Замены и очистки», удаление = пустая правая часть). Предпросмотр разбивки (панель в форме): папки + размеры в kB, чекбоксы секций (снятие = `skip` с перенумерацией, без перезапуска предпросмотра), текст главы по номеру. Настройки формы автосохраняются в localStorage (проект); многострочные regexp-поля (`noenv`) в `.env` не пишутся.

Стадия `batch_replace` — массовые замены: поле `replacements` — regexp-пары «паттерн -> замена» по одной на строку (пустая правая часть — удаление), уходят в CLI как `--replace`; паттерн — чистый стандартный regexp (Python `re`), регистр — inline-флагом `(?i)`; файл правил `replacements.txt` и literal-режим выплены. У стрелки срезается только её собственный пробельный хвост: пробелы паттерна значимы и перед ним, и внутри (` +$ ->` — хвостовые пробелы строк, а не битый `+$`); строка из одних пробелов — пустой паттерн, строка с битым regexp — предупреждение, а не падение стадии. Отчёт и предпросмотр печатают правила и diff через `mark_whitespace` (`·`, `\t`, `⏎`): иначе «^ + -> » (заменить одним пробелом) выглядит как «ничего не изменилось».

Стадия `wiki` — источник текста: «Готовый txt» (как раньше) или «Собрать из глав» (`source=chapters` → `--compile-chapters`, склейка `chapters/*` в память, `type` — chapter/translated/redacted/polished, `start`/`end` — диапазон, ГЛАВЫ). Формат вывода: `md` (обычный Markdown), `rulate-md`, `rulate-html` (заголовки — `span font-size`, `<ul>`, `<hr />`, выход `wiki.txt` — HTML-разметка внутри txt). Оглавление (`toc`) и якоря-ссылки (`toc_links`) — только в обычном режиме; у rulate-режимов содержания нет. «Сохранить как главу вики» (`as_chapter` → `--as-chapter`): вместо файла — дополнительная последняя глава `chapters/00000_{N+1}_Wiki_Новеллы/` с ОДНИМ файлом выбранного типа (`save_type` → `--save-type`: translated/redacted/polished, по умолчанию polished; `chapter.txt` не пишется), название «Wiki Новеллы» простым текстом, статьи в rulate-стиле (заголовки глубже). Компилятор: глава без «Глава N» берёт заголовок из первой непустой строки файла — вики-глава попадает в TOC epub/fb2 как «Wiki Новеллы», внутренние `###`/`####` остаются текстом в теле и пунктов содержания не создают. Режим `titles` компилятора выпилен (вкладка «Главы» правит названия прямо в файлах).

## Архитектура (контракт)

- Общая логика — только из `core/` (`core.common`, `core.projects`); web замкнут на core + собственные модули: `server.py`, `auth.py`, `sandbox.py`, `api.py`, `jobs.py`, `stages.py`, `pipeline.py`, `multipart.py`, `state.py`.
- REST-хендлеры разложены по доменам: `api.py` — фасад (порядок регистрации роутов и точка входа `register()`), а тела хендлеров в `api_common.py` (служебное, ctx, кешы, константы, сессия и вход), `api_projects.py` (пульт и проекты), `api_files.py` (файлы), `api_glossary.py` (глоссарий, review, промпты, metadata), `api_env.py` (страница «Настройки» и профили LLM), `api_assets.py` (обложка, логи, отчёты), `api_search.py` (поиск по текстам книги), `api_stage.py` (запуски, стадии и предпросмотр запроса) и `api_templates.py` (шаблоны). Общий mutable-контекст (кеши статистики и опций стадий) живёт в `api_common`: фасад реэкспортирует те же объекты, поэтому `api.<имя>` в тестах и в `main.py` — тот же словарь, а копия. Имена роутов при раскладке не менялись.
- LLM-запросы — только через `core.common.stream_chat_completion`; HTTP-транспорт за ней — `core.transport` (`open_stream`, единственный клиент — httpx; в web/http-клиент напрямую не ходит); активный стек библиотек сервер пишет в лог при старте (`core.deps`); web запускает стадии как subprocess (JobManager: Popen c `start_new_session` (Windows — `CREATE_NEW_PROCESS_GROUP`) + reader-поток + SSE; остановка дерева процессов — `_kill_tree`: POSIX killpg по группе, Windows `taskkill /F /T`). Конвейер — `web/pipeline.py` (CLI-исполнитель с `@@CHAPTER@@`-событиями для таблицы глав).
- Секреты: при `--auth` значения .env в браузер не отдаются (маска — точка на символ значения); без auth (доверенная LAN) — видны. api_key не попадает ни в payload, ни в jobs.json (только argv subprocess).
- Прогресс: `payload().progress` и `_serialize` (jobs.json) несут последнее событие прогресса `{type,label,done,total}`; SSE-тип `progress` (начальный бурст + живые события); дашборд рисует мини-бары (активные запуски + колонка «Прогресс»).
- SPA: vanilla JS + CodeMirror/marked (локальные библиотеки в `static/vendor/`, без CDN в рантайме, без сборки; версии, лицензии и sha256 — манифест `static/vendor/vendor.lock.json`, гейт `python3 tools/vendor_assets.py check`). Alpine.js удалён: SPA на ванильном JS.
- SPA-слои: `ui-core.js` — чистые функции (format, сортировки, `menuPlacement`, `toggleUiTheme`, `parseRoute`, `projectPrefs` (состояние вкладок книги: один ключ `nmTab:<раздел>/<книга>`, `get(вкладка)`/`set(вкладка, объект)`; недоступное хранилище читается пустым и молчит при записи): сегменты hash-маршрута раскодировываются — браузер хранит хэш закодированным, и раздел с кириллическим именем иначе доезжал до API дважды закодированным и проект не находился), `ui-components.js` — общий DOM-слой: фабрика `h`, `iconEl` и каркасы `modal` (оверлей+карточка, обещание диалога через `onClose`), `menuButton`, `previewPane` (редактор + sandbox-iframe, режимы code/md/html/text; кнопка переключения называется тем, что показывает: «Рендер» в коде, «Редактор» в предпросмотре) и `listPager` (список+страницы; режимы `infoOnlySinglePage`, `hideSinglePage`, `hideOnEmpty` и управляемый — только счётчик). View-файлы (`app.js`, `project-views.js`, `run-views.js`) описывают данные и разметку; повторять общий каркас в них нельзя.
- Проверка SPA: `./dev.sh spa` (`node --check` по всем файлам + `node --test tests/spa/` — DOM-mock, без браузера) и `./dev.sh probe` (headless-обход на временных данных, `tools/ui_probe.mjs`).
