# Справка

## О программе

**NovelMaestro** — конвейер перевода китайских веб-новелл (zh → ru) на
базе LLM (OpenAI-совместимых языковых моделей) с человеческими
контрольными точками на каждом этапе.

Идея: автоматизировать рутину перевода — разбор исходника, извлечение
глоссария имён и терминов, сам перевод, проверки, сборку в готовые
форматы, — но оставить ключевые решения за человеком: выбор промптов,
проверку качества, финальную корректуру.

Интерфейс один — **web** (страница в браузере). Сервер поднимается
командой `python3 run.py` (на Windows — `python run.py`), после чего
открывается браузер с интерфейсом. Слева — панель навигации: Дашборд,
Проекты, Настройки, Шаблоны, Заметки и Справка (этот раздел).

### Как устроен перевод

Каждая книга проходит восемь стадий (в порядке карточек на странице
«Запуски» проекта):

1. **Разбор исходника на главы** — EPUB/TXT превращается в папки глав;
2. **Создание глоссария (LLM)** — из текста извлекаются имена, термины,
   локации в `ner.json`;
3. **Проверка глоссария (LLM)** — LLM предлагает правки глоссария,
   человек принимает/отклоняет их;
4. **Перевод (LLM)** — конвейер: перевод → редактура → полировка;
5. **Проверка перевода** — алгоритмическая сверка оригинала и перевода
   (длины, покрытие);
6. **Проверка перевода (LLM)** — LLM ищет ошибки в переведённых главах,
   человек применяет правки;
7. **Компиляция** — сборка готовых TXT / EPUB / FB2;
8. **Wiki (LLM)** — генерация wiki-компендиума по глоссарию и тексту.

Между стадиями 4 и 5 также доступны **массовые замены** — быстрые
регулярные замены по всем главам без LLM.

## Управление проектами

### Разделы

Проекты лежат в папке `projects/` и организованы по **разделам**:

- **ACTIVE** — текущие проекты в работе;
- **HOLD** — приостановленные;
- **DONE** — завершённые.

Разделы динамические: можно создавать свои, переименовывать и удалять
(непустой раздел удалить нельзя — сначала перенесите или удалите
проекты). Управление — вкладка «Проекты» → кнопка «Управление
разделами».

### Создание проекта

Во вкладке «Проекты» выберите раздел и нажмите **«＋ Создать новый
проект…»**. Мастер спросит по порядку:

1. **Раздел** — по умолчанию ACTIVE;
2. **Английское имя** — имя папки проекта (пробелы заменяются на `_`,
   запрещённые символы удаляются; итоговое имя показывается заранее);
3. **Русское название, автор, жанры** — опционально, попадают в
   `source/metadata.yaml`;
4. **Тип книги** — подпапка `templates/` с промптами (по умолчанию
   `General`): её файлы `prompts/` и `source/` копируются в проект.

Опционально можно сразу загрузить обложку (jpg/png) и исходник книги
(txt/md/epub/zip).

### Управление проектом

На карточке проекта (меню «⋯») доступны:

- **перенос между разделами** (при переносе из ACTIVE в DONE —
  подтверждение);
- **переименование**;
- **дублирование** — копия для альтернативного перевода;
- **статистика** — главы, артефакты, глоссарий, wiki и путь к папке;
- **удаление** — только после ввода слова `УДАЛИТЬ`.

### Настройки проекта

Конфигурация — вкладка **«Конфиг»** внутри проекта:

- **Системный `.env`** — общие настройки LLM-сервера (хост, ключ,
  модель) и web-сервера. Лежит в корне `projects/` (системный) или в
  папке проекта (`pdir/.env`, приоритетнее для конкретной книги);
- **Обложки и метаданные** — загрузка нескольких вариантов обложек и
  YAML-наборов метаданных в `source/`, выбор варианта по умолчанию
  для компиляции;
- **metadata.yaml** — метаданные книги для EPUB/FB2;
- **внешний вид** — тема интерфейса, тема редактора, кегль
  (системный `.env`, ключи `WEB_UI_THEME` / `WEB_EDITOR_THEME` /
  `WEB_EDITOR_FONT_SIZE`).

Приоритет конфигурации: **CLI-флаг > окружение > `.env` > встроенный
дефолт**. Без `.env` программа не падает — предложит ввести параметры
вручную. Файлы `.env` содержат API-ключи и не коммитятся в git.

## Работа с проектом

### Общие принципы

- **Главы.** Каждая глава — папка в `chapters/` с именем вида
  `00000_1_Заголовок` (нули + номер + название). Внутри — артефакты
  стадий:
  `chapter.txt` (оригинал) → `translated.txt` (черновой перевод) →
  `redacted.txt` (после редактуры) → `polished.txt` (финальная версия).
  Имена артефактов фиксированы и не меняются.
- **Глоссарий** — `ner.json` в корне проекта: термины с полями
  `term`, `translation`, `type`, `count` и т.п. Глоссарий используется
  на стадиях перевода, редактуры и полировки.
- **Промпты** — файлы в `prompts/` проекта: один файл на стадию или
  общий файл с тегами `<translate>/<redact>/<polish>`.
- **Логи** — `logs/` (прогоны стадий) и `logs/chapters/` (по главам).

### Вкладка «Файлы»

Браузер файлов проекта: навигация по каталогам, просмотр, правка,
загрузка (multipart), скачивание. Можно создавать файлы и каталоги
(«＋ Файл», «＋ Каталог»), переименовывать, удалять. Большие файлы
(> 5 МБ) не открываются в редакторе — только скачивание.
Песочница: запрещён выход за пределы проекта (`..`, абсолютные пути,
симлинк-побег).

### Вкладка «Редактор»

Редактор CodeMirror для глав проекта:

- **Панели** Оригинал / Перевод / Редактура / Полировка: по умолчанию
  слева оригинал, справа полировка (или редактура/перевод, если
  полировки ещё нет). Канонические файлы видны, даже если их ещё нет —
  сохранение создаст файл;
- **Подсветка терминов глоссария** оверлеем — можно включить/выключить,
  настроить n-грамму и порог нечёткого поиска;
- Выделение фрагмента в `chapter.txt` — кнопка «＋ в глоссарий»
  (термин, тип, перевод);
- поиск/замена Ctrl+F / Ctrl+H, предпросмотр md/html («Рендер»).

### Вкладка «Глоссарий»

Таблица `ner.json`: инлайн-редактирование строк, настраиваемые столбцы
(все поля, выбор в localStorage), сортировка кликом по заголовку
(по умолчанию — `count` по убыванию), добавление/удаление терминов,
поиск по выбранным полям. Выбор столбцов/полей/типов — единая модалка
«Все / набор» (всё снять нельзя — остаётся первый пункт).
Экспорт глоссария для анализа — JSON / записи текстом / имена по полу
(фильтры: порог count, типы, исключения, диапазон).

### Вкладка «Проверка»

Здесь живут результаты проверок:

- **Отчёты translate_check** — таблица «глава → папка → ошибки» с
  переходом в «Файлы», FATAL подсвечен;
- **LLM-карточки** (`ner_review.json` / `translate_check_llm_review.json`)
  — переключатель «Список правок / Редактор JSON»: список правок со
  сводкой (всего / принято / отклонено / применено), кнопки «Принять»,
  «Отклонить», «Откорректировать» (Было / Стало / Причина), переход к
  тексту правки («→ Глава» — файл главы с поиском фрагмента,
  «→ Глоссарий» — таб с поиском термина). Применение — фоновая задача
  с уведомлением; чекбокс «не создавать .bak» (по умолчанию бэкапы
  создаются).

### Вкладка «Главы»

Названия глав: чтение и замена первой строки файлов глав (тип —
chapter/translated/redacted/polished). Заголовок главы — первая строка
файла; замена происходит по NFC-нормализации, результат — отчёт
`updated / missing / warnings`.

### Вкладка «Статус»

Таблица готовности глав: по-главные флаги translate / redact / polish
плюс ner / wiki / compiled. Кешируется по сигнатуре mtime.

### Вкладка «Конфиг»

См. раздел «Управление проектами → Настройки проекта»: системный и
проектный `.env`, обложки и метаданные, metadata.yaml, внешний вид.
При `--auth` значения `.env` маскируются (`••••`).

### Вкладка «Промпты»

Файлы `prompts/` проекта + шаблоны `templates/*/prompts` в одном
списке; создание промпта из шаблона; редактор с предпросмотром
md/html. Промпты стадий:

| Стадия | Файл по умолчанию | Теги (общий файл) |
| --- | --- | --- |
| Перевод | `translate_prompt.txt` | `<translate>` |
| Редактура | `redact_prompt.txt` | `<redact>` |
| Полировка | `polish_prompt.txt` | `<polish>` |
| Глоссарий | `ner_prompt.txt` | `<prompt_pass1>`, `<prompt_pass2>` |
| Проверка глоссария | `ner_check_prompt.txt` | — (файл целиком) |
| Проверка перевода (LLM) | `translate_check_prompt.txt` | `<pass1>/<pass2>` |
| Wiki | `wiki.txt` | `<prompt_wiki_article>` |

Плейсхолдеры: `{ner_block}` (translate/redact/polish),
`{original_text}` / `{translated_text}` (redact),
`{female_names}` / `{male_names}` (имена из глоссария по полу).

### Вкладка «Логи»

Список `logs/` и `logs/chapters/`, хвост, follow (автообновление),
удаление логов. История запусков — здесь (страница «Запуски» историю
не показывает).

### Вкладка «Заметки»

Общие заметки по проекту — `projects/notes.md`, markdown-редактор с
предпросмотром в sandbox-iframe.

## Шаблоны

Каталог `templates/` — стартовые файлы для новых проектов:

- **Общие шаблоны** в корне: `.env.example` (конфиг LLM + web),
  `donate.txt.example` (страница поддержки), `replacements.txt.example`
  (правила массовых замен);
- **Наборы по типу книги** — подпапки (`General/` — универсальный):
  `prompts/` (стартовые промпты) + `source/` (metadata.yaml, donate.txt).

При создании проекта выбирается тип книги — набор копируется в проект
(без перезаписи существующих файлов).

Вкладка «Шаблоны» позволяет:

- просматривать и **редактировать** файлы набора (в т.ч. `General` —
  системный набор, его можно только читать);
- **создавать новые наборы** (каркас `prompts/` + `source/`),
  копировать, удалять;
- загружать файлы в набор (в `General` — нельзя).

## Запуски

### Общая информация

Стадии запускаются на странице «Запуски» проекта (кнопка «▶ Запуски»
в шапке проекта). Каждая стадия — карточка с формой параметров и
кнопкой «Запустить».

Над формой — переключатель **«Простой режим / Экспертный»**:

- **Простой режим** — карточка пресета («что будет сделано» +
  диапазон глав) и минимум полей; LLM-поля не показываются — сервер,
  ключ и модель берутся из `.env`. Выбор режима запоминается по
  стадии в localStorage браузера;
- **Экспертный режим** — все поля формы: диапазон глав, промпты,
  LLM-поля (host/model/api_key), размеры чанков, потоки и т.п.

Значения формы общие для обоих режимов: правки в экспертном применяются
в простом и наоборот. Поля форм предзаполняются из `.env` и при каждом
запуске сохраняются обратно (ключи `<СТАДИЯ>_<ПОЛЕ>`).

**Во время запуска** — живой лог (SSE-стрим), прогресс-бар для
LLM-стадий, для конвейера перевода — таблица глав с галочками
✓/✗. Кнопка **«Стоп»** останавливает запуск (вместе с дочерними
процессами). Два параллельных запуска на один проект запрещены,
лимит параллельных запусков — `WEB_JOBS_LIMIT`.

История запусков — во вкладке «Логи» проекта и на «Дашборде»
(«Последние запуски»).

### Разбор исходника на главы (epub)

Стадия **«Разбор исходника на главы»** (`epub_to_chapters`), без LLM.
Исходник — `.epub` или `.txt` из `source/` (ZIP не принимается).

Режимы разбивки:

- **По TOC (epub)** — разбивка по структуре книги (spine/TOC/h1-h2);
- **Ручная (regexp)** — строки-маркеры: каждый паттерн задаёт начало
  новой главы, вся строка становится заголовком (пример: `Глава \d+`);
- **По чанкам** — режем текст на куски по `chunk_size` (СИМВОЛЫ), маска
  названия вида `Глава {num}`.

Дополнительно: очистки текста (паттерны-удаления, работают во всех
режимах), замены `паттерн -> замена` (до разбивки, удобно нормализовать
маркеры: `第(\d+)章 -> Глава \1`), лимит длины названия папки, смещение
нумерации, тип выходного файла (`chapter.txt` по умолчанию), очистка
старых папок глав. Есть предпросмотр разбивки с удалением секций.

### Создание глоссария (ner)

Стадия **«Создание глоссария (LLM)»** (`ner`). Режимы:

- **С нуля** — новый `ner.json` из txt;
- **Дообучение** — термины добавятся к существующему `ner.json`;
- **Собрать главы + извлечение** — склейка `chapters/*/chapter.txt` в
  память (можно ограничить диапазоном) и извлечение;
- **Постобработка** — обработка `ner.json` без LLM: `strip_meta`
  (удалить служебные поля), `min_count` (фильтр по частоте).

Двухпроходная схема (по умолчанию включена) улучшает качество
извлечения. Параметры: размер чанка (СИМВОЛЫ), порог дедупликации,
n-граммы для латиницы, поля для «голосования» при схлопывании дублей
(translation/type/pinyin), интервал сохранения кэша, повторы.

### Проверка глоссария (ner_check)

Стадия **«Проверка глоссария (LLM)»** (`ner_check`) отправляет
глоссарий LLM, получает правки и пишет их в `ner_review.json` —
человек принимает/отклоняет во вкладке «Проверка», затем применяет.
LLM на этапе применения не нужен.

Рекомендуемый двухэтапный режим:

1. **Весь список** (`whole`) — LLM проверяет весь глоссарий разом;
   правки → review; человек правит статусы; «Применить»;
2. **По типам** (`types`) — каждая группа типов отдельно, уже по
   обновлённому глоссарию; правки дописываются в тот же review-файл;
   снова человек и «Применить».

Режим **«Всё»** (`all`) — этапы 1+2 подряд. `--auto-apply` — авторежим
без человека (whole → применение → types). Батчи режутся по бюджету
`batch_size` (СИМВОЛЫ). Применение делает бэкап `ner.json.bak` и пишет
лог применённых правок в `ner_changes.md`.

### Перевод (pipeline)

Стадия **«Перевод (LLM)»** (`pipeline`) — конвейер над главами:

- **Перевод** — `chapter.txt` → `translated.txt` (с контекстом и
  глоссарием);
- **Редактура** — замена терминов по глоссарию,
  `translated_trace.json` → `redacted.txt`;
- **Полировка** — стилистическая шлифовка, `redacted.txt` →
  `polished.txt`.

Тип работы (action): перевод, редактура, полировка (с разными
исходниками), сокращённые циклы (перевод→редактура, перевод→полировка,
редактура→полировка) и полный цикл (перевод→редактура→полировка).
Параметры: общий промпт-файл (теги `<translate>/<redact>/<polish>`;
пусто = авто-поиск по `prompts/`), диапазон глав (ГЛАВЫ), параллельные
потоки (jobs, 1–16), потоки на главу (threads), таймаут, температура,
reasoning effort. Промпт для каждой стадии подставляется автоматически;
недостающий тег — предупреждение в логе + встроенный промпт.

### Проверка перевода (translate_check)

Стадия **«Проверка перевода»** (`translate_check`), без LLM:
алгоритмическая сверка оригинала и перевода — длины, покрытие, слова
исключения. Пресет сравнения: polished / redacted / translated.
Диапазон глав, мягкий режим (`--lenient`), слова-исключения
(`TRANSLATE_CHECK_EXCLUDE_WORDS`, дефолт `VIP,MVP,【,】,NPC`).
Результат — отчёт в `logs/`, просмотр — вкладка «Проверка».

### Проверка перевода (LLM) (translate_check_llm)

Стадия **«Проверка перевода (LLM)»** (`translate_check_llm`) ищет
ошибки в главах (тип файла: polished / redacted / translated) через LLM
и пишет человекочитаемый накопительный файл
`translate_check_llm_review.json` (поля: chapter, file, old/new, type,
reason, status принять/отклонить, applied). Человек правит статусы во
вкладке «Проверка» → «Применить» (бэкап `.bak` у каждой изменённой
главы). `--two_pass` — второй проход верификации находок. Параметры:
бюджет контекста на пакет (СИМВОЛЫ), лимит правок на главу, минимальная
длина правки, макс. изменённых символов, потоки.

### Массовые замены (batch_replace)

Стадия **«Массовые замены»** (`batch_replace`), без LLM и без
интерактива: применяет к главам список regexp-замен (поле
«Regexp-замены», по одной паре на строку `паттерн -> замена`; пустая
правая часть — удаление). Тип файлов глав, диапазон, предпросмотр
(`--dry-run`). Полезно для финальной чистки имён и терминов в готовых
главах.

В CLI (вне web) поддерживается и файл правил `prompts/replacements.txt`
(шаблон — `templates/replacements.txt.example`): одна замена на строку,
флаги `|i` (регистр) и `|r` (regex с обратными ссылками `\1…\9`) в
конце строки, строки `## …` — секции для отчёта.

### Компиляция TXT/EPUB/FB2 (compile)

Стадия **«Компиляция TXT/EPUB/FB2»** (`compile`), без LLM: собирает
главы в TXT, EPUB или FB2 (нативно, stdlib). Режимы: txt / epub / fb2
и «частями» (epub-chunks / txt-chunks / fb2-chunks, размер части —
глав). Исходный файл главы — polished / redacted / translated / chapter.

**Обложка и метаданные.** Варианты обложек (`source/cover.*`) и
YAML-наборов метаданных выбираются в форме (или в «Конфиге»); пусто =
авто (`cover.*` / `metadata.yaml`). Для FB2 можно отключить обложку.

**Страница поддержки** — `source/donate.txt` (или `prompts/donate.txt`),
шаблон `templates/donate.txt.example`; чекбокс «Без страницы поддержки».

Заголовок главы: первое «Глава N» в файле → иначе первая непустая
строка («Пролог. Пример» → название) → иначе «Глава N». Выходные файлы:
`compiled_<start>_<end>_<mode>.txt`, `<ИмяПроекта>_<start>_<end>.epub/fb2`.

### Создание Wiki (LLM) (wiki)

Стадия **«Создание Wiki (LLM)»** (`wiki`) генерирует wiki-компендиум по
глоссарию и тексту. Источник текста: готовый txt или «Собрать из глав»
(склейка `chapters/*`, тип chapter/translated/redacted/polished,
диапазон). Формат: обычный Markdown, rulate-md, rulate-html
(заголовки `span font-size`, `<ul>`, `<hr />`). Оглавление и якоря —
только в обычном режиме.

«Сохранить как главу вики» — вместо файла дополнительная последняя
глава `chapters/00000_{N+1}_Wiki_Новеллы/` с одним файлом выбранного
типа (polished по умолчанию). Параметры: макс. терминов, мин. частота,
исключение/белый список типов, фрагментов контекста на термин,
NEAR-дистанция (ТОКЕНЫ), размер чанка FTS5 (СИМВОЛЫ), пары типов для
связей и их число.

## Регулярные выражения

### Диалект

В NovelMaestro используется диалект **Python `re`** — тот же, что в
языке Python (regex101 в режиме Python). Это не PCRE: поддерживаются
основные конструкции — классы символов, квантификаторы, группы,
якоря, ленивые квантификаторы `*?` `+?` `??`, lookahead/lookbehind
(`(?=…)`, `(?!…)`, `(?<=…)`, `(?<!…)`), именованные группы. Регистр —
по умолчанию чувствителен (флаг `|i` отключает), юникод включён.

Где применяются regexp в интерфейсе:

- **Разбор исходника** — паттерны разбивки, очистки, замены;
- **Массовые замены** — поле «Regexp-замены» и файл правил
  `replacements.txt` (флаг `|r`);
- **Прямой запуск скриптов** — `--split-re`, `--replace-re`,
  `--replace`.

### Основы

| Конструкция | Значение | Пример |
| --- | --- | --- |
| `abc` | литерал: точное совпадение строки | `Глава` |
| `.` | любой символ (кроме переноса строки) | `Глава.` — «Глава1» |
| `\d` `\w` `\s` | цифра / буква / пробельный | `\d+` — число |
| `[а-я]` `[0-9]` | класс символов (диапазон) | `[А-ЯЁ]` — заглавная |
| `[^…]` | отрицание класса | `[^ ]+` — всё до пробела |
| `*` `+` `?` | ноль+ / один+ / ноль-один | `\d*` — цифр может не быть |
| `{n,m}` | от n до m повторов | `\d{2,4}` |
| `^` `$` | начало / конец строки | `^本章完` — строка-маркер |
| `(…)` `\|` | группа / альтернатива | `Хунг(а\|у\|ом\|е)` |
| `\b` | граница слова | `\bГлава\b` |
| `\\.` `\\(` | экранирование спецсимвола | `\.` — точка |

В строках форм символы вводятся как есть (одна обратная косая черта);
при прямом запуске из командной строки в bash может понадобиться
двойное экранирование (`"Глава \\d+"`).

### Обратные ссылки

**Обратные ссылки** позволяют использовать часть совпадения (группу)
в замене. Группы нумеруются с 1 по порядку открывающих скобок:
`\1`, `\2`, … `\9`; `\g<0>` — всё совпадение целиком; `\g<имя>` —
именованная группа.

Примеры в формате NovelMaestro `паттерн -> замена`:

- `第(\d+)章 -> Глава \1` — «第12章» → «Глава 12» (группа `(\d+)` —
  номер главы, `\1` вставляет его);
- `Хунг(а|у|ом|е) -> Хун\1 |r` — склонения: «Хунга» → «Хуна»,
  «Хунгу» → «Хуну» и т.д.;
- `Глава \d+ -> Глава №\g<0>` — «Глава 5» → «Глава №Глава 5» не
  получится: `\g<0>` вставляет всё совпадение, т.е. «Глава №5»
  правильнее записать как `Глава №\d+` через захват:
  `Глава (\d+) -> Глава №\1`.

> Внимание: в файле правил `replacements.txt` обратные ссылки —
  `\1…\9`; в поле «Regexp-замены» интерфейса работают и `\g<0>`,
  и `\g<имя>`.

### Примеры с разбором

#### 1. Нормализация маркеров глав (разбор исходника)

```text
第(\d+)章 -> Глава \1
```

«第3章 测试» → после замены «Глава 3 测试». Паттерн: литерал «第»,
группа `(\d+)` захватывает номер, литерал «章». Замена — «Глава » +
`\1` (номер из группы). Режим: поля «Замены» стадии разбора исходника.

#### 2. Удаление мусора из текста (разбор исходника, очистки)

```text
^本章完
```

Каждая строка, которая *начинается* с «本章完» (якорь `^`), удаляется
целиком; пустые строки после этого сжимаются. Поле «Очистки текста».

#### 3. Склонение имени (массовые замены)

```text
Хунг(а|у|ом|е) -> Хун\1 |r
```

Группа-альтернатива `(а|у|ом|е)` ловит окончание; `\1` возвращает его
в замену — «Хунга» → «Хуна», «Хунгу» → «Хуну», «Хунгом» → «Хуном»,
«Хунге» → «Хуне». Флаг `|r` включает regex-режим (в `replacements.txt`).

#### 4. Удаление HTML-тегов (массовые замены)

```text
<[^>]+> ->
```

Паттерн: `<`, класс-отрицание `[^>]+` (любые символы до `>`), `>`;
правая часть пустая — совпадения удаляются. Ленивый вариант —
`<.*?>` с `.*?` (нежадный квантификатор).

#### 5. Точный термин с границами (массовые замены)

```text
\bСюань\s+Цин\b -> Сюаньцин |r
```

`\b` — границы слова, `\s+` — один и более пробельных символов:
«Сюань Цин» → «Сюаньцин» (пробельные символы съедены), но слово
«Сюаньцин» без пробела не заденет.

#### 6. Диапазон глав (прямой запуск разбора)

```text
--split-re "Глава \d+"
```

Каждая строка, начинающаяся с «Глава <число>», становится заголовком
новой главы (вся строка — название папки главы).

### Проверка регулярных выражений

Готовые выражения удобно проверять на [regex101](https://regex101.com/)
в режиме Python. Помните: в интерфейсе NovelMaestro разделитель пары —
`->` (первое вхождение), пустая правая часть — удаление, строки,
начинающиеся с `#`, — комментарии.
