# История версий NovelMaestro

## 0.2.5

### Изменения

- **translate_check: флаг « |s» в regexp-проверках** — «пропустить
  первое совпадение»: правило `^\s*Глава\s+\d+ |s` ловит лишние
  заголовки «Глава N», не помечая сам заголовок главы; комментарий
  « # …» и флаг в одной строке; справка в форме стадии дополнена.

### Исправления

- **Запуски: живой лог и статусы** — SSE-стрим не подключался
  («Assignment to constant variable»), лог был пуст, статус
  (остановлен/готово) приходил только после перезагрузки страницы.
- **Предпросмотр запроса LLM** — модалка падала «can't convert null
  to object» на всех стадиях (null-атрибуты в h()).
- **Проверки: «Применить»** — кнопка запускала полный LLM-прогон
  вместо применения правок ner_review.json (флаги apply/dry_run/
  no_bak потеряны при рефакторинге build_ner_check); apply-флаги
  больше не пишутся в pdir/.env.
- **Запуски: чипсы полей/типов** — выбор в чипсах-чекбоксах
  (поля {ner_block}, типы глоссария) переживает перезагрузку
  страницы (localStorage per проект+стадия), дефолт помечается
  как выбранный явно — «видимое = отправляемое».
- **Конвейер: --no-aliases** — оркестратор передавал несуществующий
  флаг --no_aliases; при снятых алиасах запуск и предпросмотр
  падали на argparse стадии 1.

## 0.2.4

### Изменения

- **Запуски: лог последнего завершённого запуска остаётся на вкладке
  стадии** — панель лога показывается для текущего запуска стадии в
  любом статусе (после завершения остаётся с финальным статусом и
  временем) либо — последний завершённый запуск ЭТОЙ стадии этого
  проекта (лениво из истории запусков, кэш по стадии); лог всегда
  соответствует открытой вкладке, новый запуск переключает панель на
  активный (live-гард: строки чужого запуска не утекают в историю);
  `/api/jobs/{id}` отдаёт лог целиком (весь кольцевой буфер, не 500
  строк).
- **Конвейер: выбор полей терминов в `{ner_block}`** — чипсы-чекбоксы
  в обоих режимах формы (как «Поля в запросе LLM» в ner_check):
  базовые type/translation/aliases + ключи из реального ner.json
  проекта; выбор общий для всех 3 стадий конвейера (`--ner_fields`),
  снятие aliases отключает авто-добавление алиасов (`--no_aliases`).
- **ner: границы предложений любых языков и нечёткий контекст
  термина** — в поле context поглощаются закрывающие кавычки/скобки
  после знака конца предложения; знаки конца любых языков (арабский,
  урду, деванагари, армянский, эфиопский); фолбэк: нечёткий поиск
  термина по предложениям чанка (n-грамм-перекрытие + longest match,
  порог = `--threshold` стадии ner; CJK — только точный).
- **Предпросмотр запроса LLM** — кнопка (только Экспертный режим) у
  всех LLM-стадий (pipeline, ner, ner_check, translate_check_llm,
  translate_quality, wiki): эмуляция ПЕРВОГО запроса стадии без сети
  (чанк/батч/термин 1 — из того же кода сборки, что реальный запуск;
  артефакты и логи не создаются) + модалка с сообщениями system/user,
  статистикой символов и параметрами; API — `POST
  /api/stages/{key}/preview-request` (таймаут 300 с).

## 0.2.3

### Изменения

- **translate_check: настраиваемые структурные проверки** — минимальный
  размер файла — отдельное поле `--min-file-size` (БАЙТЫ, дефолт 3072);
  заголовок главы — отдельный regexp `--header-regexp` (пусто =
  «Глава N» без учёта регистра); «Проверять последовательность глав»
  — отключаемый чекбокс (`--no-sequence-check`, по умолчанию включён):
  первое число в первой непустой строке должно быть ровно на 1 больше
  предыдущего (N+1); лишние заголовки «Глава N» перенесены из
  структурной проверки в дефолтный набор regexp-проверок — первое
  совпадение (сам заголовок главы) не ошибка, последующие — «Лишний
  заголовок главы», паттерн наследует настраиваемый `--header-regexp`.

### Исправления

- **Вкладка «Главы»** — диапазон задаётся двумя полями (начало/конец,
  как в «Запусках»); строки идут в порядке номеров: существующие главы
  на своих местах, пропущенные — серыми ячейками «N —»; удаление
  файлов — модалка с подтверждением словом УДАЛИТЬ.
- **Форма «Оценка перевода»** — падение при неопределённом выбранном
  промпте: пересчёт конечной главы не вешается на отсутствующий
  элемент.
- **`templates/.env.example`** — комментарии вынесены отдельными
  строками (без inline после значений); дефолтные regexp-проверки —
  реальные паттерны.

## 0.2.2

### Изменения

- **Бюджет LLM-запросов — только содержимое** — длина промпта больше
  не вычитается из бюджета: `--budget`/`--rag_budget`/`--chunk_size`
  ограничивают только главы/фрагменты/пакеты (СИМВОЛЫ), промпт идёт
  сверх бюджета. Применено к «Оценке перевода» (CLI и web-калькулятор
  конечной главы) и RAG-режиму ner_check.
- **Конвейер: суммарные потоки** — поля «Параллельных глав» и «Потоков
  на главу» объединены в одно «Потоков (1–16)»: задаётся СУММАРНОЕ
  число одновременных LLM-запросов, распределение по главам и чанкам
  считает web-оркестратор (`--threads` убран).
- **ner_check · RAG: термин = запрос** — каждый термин проверяется
  отдельным LLM-запросом (раньше все термины уходили одним гигантским
  пакетом); запросы идут параллельно, «Параллельные пакеты» — число
  одновременных запросов; бюджет на термин — только фрагменты книги.
- **ner_check: теги промптов** — промпт «Выбранные типы» обёрнут
  в `<prompt_check>`, RAG — в `<prompt_rag>`; комментарии в
  промпт-файлах пишутся вне тегов строкой с `#` (единообразно с
  остальными промптами).
- **translate_check: проверки и форма** — ищутся ВСЕ иероглифы (все
  CJK-блоки, а не только `[一-鿿【】「」『』]`); regexp-проверки сканируют
  все строки включая заголовок главы; лишние заголовки «Глава N»
  находятся структурно; каждая найденная ошибка — отдельной строкой
  (клик по ошибке ищет одно вхождение, а не весь список). Поля
  переименованы: «Выбранная Стадия/Предыдущая Стадия (по занимаемому
  месту)» и «Выбранная Стадия/Оригинал (по занимаемому месту)»;
  дефолтные значения полей переехали в системный `.env`
  (`TRANSLATE_CHECK_NEIGHBOR`/`TRANSLATE_CHECK_ORIGINAL`/
  `TRANSLATE_CHECK_REGEXP_CHECKS`) — пустой `.env` = пустое поле;
  флаг `--lenient` из web убран.
- **Конфиг и Docker** — `templates/.env.example`: `HOST=` пусто
  (сервер задаётся пользователем), дефолты translate_check;
  docker-compose переопределяет их переменными окружения (включая
  `TZ` для местного времени); в образ добавлен `tzdata`.
- **Отчёт «Оценка перевода»: местное время** — дата отчёта пишется
  локальным временем (`datetime.now().astimezone()`), а не UTC.
- **Вкладка «Главы»** — диапазон глав одной строкой (как в «Запусках»,
  префилл — весь диапазон); кнопка «Удалить файлы» стирает файлы
  выбранного типа в диапазоне (с подтверждением); пропущенные главы
  показываются серыми ячейками «N —» (корректно в светлой и тёмной
  темах). API: `GET …/chapters/titles` отдаёт `all_ids`/`missing`,
  добавлен `DELETE …/chapters`.

## 0.2.0

### Новое

- **Стадия «Оценка перевода (LLM)»** — `translate_quality` между
  «Массовые замены» и «Компиляция TXT/EPUB/FB2»: один LLM-запрос по
  пакету глав диапазона; `{original_text}` (chapter.txt) и
  `{translated_text}` (тип файлов глав) подставляются в промпт
  (тег `<prompt_assessment>`, шаблон в `templates/General/prompts/`).
- **Простой/Экспертный режимы** — простой: диапазон глав, тип
  файлов, промпт-файл; экспертный: + стандартные LLM-поля (сервер,
  модель, API-ключ, таймаут, повторы, температура, reasoning
  effort) и бюджет запроса в СИМВОЛАХ (главы + промпт); если главы
  не влезают — пакет обрезается до целого количества глав, отсечённые
  указываются в отчёте.
- **md-отчёт оценки** — `translation_quality_assessment.md`
  (настраиваемый выход): техническая шапка (дата, диапазон, пакет,
  бюджет, модель) + оценка LLM; вкладка «Проверки» → «Оценка
  перевода (LLM)» рендерит отчёт (выбор md-файла, дефолт
  `translation_quality_assessment.md`).
- **compile · «Тип файлов глав»** — поле `source_type` переименовано
  (было «Исходный файл главы»).

### Новое · translate_check

- **translate_check · «Тип файлов глав» вместо пресета** — выбор
  типа (polished/redacted/translated) определяет сравнения:
  polished → redacted+chapter, redacted → translated+chapter,
  translated → только chapter; простой режим с карточкой
  «Проверить перевод».
- **translate_check · «ratio±tol» в одном поле** — «Стадия/Стадия
  (по занимаемому месту)» и «Оригинал/Стадия (по занимаемому
  месту)» вместо четырёх полей ratio/tol; формат `1.0±0.05`
  (`--neighbor`/`--original`).
- **translate_check · универсальные regexp-проверки** — чекбоксы
  отключения и «свои форматы» убраны: каждая строка — regexp по
  тексту главы (multiline), всё найденное — ошибка, первое
  вхождение на заголовке главы не считается; по умолчанию —
  иероглифы, латиница, лишние «Глава N».
- **Комментарии « # …» в regexp-полях** — паттерны разбивки epub,
  regexp-проверки translate_check и правила batch_replace
  поддерживают комментарий в конце строки; многострочные поля
  предзаполняются из `.env` одной строкой с переносами как «\n»
  (`EPUB_SPLIT_PATTERNS`, `TRANSLATE_CHECK_REGEXP_CHECKS`,
  `BATCH_REPLACE_REPLACEMENTS`).
- **Предпросмотры при светлой теме** — явный цвет текста у
  предпросмотра замен, epub-разбивки и compile: чёрные буквы на
  тёмном фоне невозможны при любой теме.

### Изменения

- `cli/translate_check.py`: `--preset` → `--check-type`,
  `--ratio-*/--tol-*` → `--neighbor`/`--original`,
  `--no-nonrussian`/`--nonrussian-regex`/`--no-chapter-order`/
  `--chapter-regex` → `--regexp-check` (повторяемый).
- `core/common.py`: новая функция `strip_line_comment` (inline-
