# NovelMaestro Lite — юзерскрипт-читалка

Лёгкий браузерный аналог конвейера NovelMaestro: юзерскрипт для Tampermonkey/Violentmonkey, который переводит веб-новеллы (и вообще любые сайты) на русский язык через OpenAI-совместимые LLM-серверы — прямо в браузере, без сервера и установки проекта. Основной режим — **читалка**: полноэкранное окно чтения, где текст главы заменён переводом. Глоссарий терминов ведётся по книгам, извлечение терминов (NER) и перевод — со стримингом.

Публикуемый файл: `novelmaestro-lite.user.js` (версия — в метаданных файла). Он **собран из `src/`** — править его руками нельзя (перезапишет сборка), разработка идёт в `meta.js` и `src/NNN-*.js`, см. «Исходники и сборка». Расширение `.user.js` — общепринятый канон юзерскриптов: менеджеры скриптов (Tampermonkey/Violentmonkey) по нему распознают файл как устанавливаемый, а имя-слаг в kebab-case совпадает с `@name` — так скрипт выглядит в каталогах.

## Возможности

- **Режим читалки** — страница заменяется полноэкранным режимом чтения: верхняя панель (название главы, ⋮ меню и ✕ закрыть; в ⋮ — 📄 экспорт TXT, 🌐 перевести заново, 🌓 тема, ⚙️ настройки), текст главы с абзацами, нижняя панель — навигация (← предыдущая, ☰ оглавление, → следующая) и статус опережающего перевода. Перевод приходит стримингом прямо в читалку с прогресс-баром по абзацам. Внешний вид настраивается: тема (светлая «бумага»/тёмная, она же для всего UI), шрифт (Georgia/Arial/Times New Roman/Verdana/Segoe UI), размер (px, по умолчанию 14), межстрочный интервал, отступ между абзацами (em), ширина колонки — в **процентах ширины экрана** (настройка, по умолчанию 80; старые значения — пиксельные и 66% — мигрируются автоматически).
- **Обучение элементам для книги (как в uBlock Origin)** — режим из меню ⋮: наводишь курсор — элемент подсвечивается, клик — попап выбирает тип: 📄 блок основного текста (обязателен), ← «Назад», → «Вперёд», ☰ «Оглавление» (необязательные). Вместо хрупких уникальных селекторов сохраняется **сигнатура элемента**: тег, id/классы и цепочка до четырёх предков — на других главах той же книги элемент находится по структуре страницы (обучение — эвристика на всю книгу). При первом 🌐 на необученной книге обучение открывается само; после «✅ Готово» перевод стартует автоматически.
- **Навигация по главам** — ←/→ сначала ищутся по выученным сигнатурам, затем фолбэком по всей странице: `rel="next|prev"`, текст/класс/id ссылки (next/previous/вперёд/назад/след, китайские 下一章/下一页 и вьетнамские Chương trước/sau/tiếp theo), одиночная ссылка в контейнере. Это важно именно на телефоне: мобильная версия сайта часто отличается по структуре от десктопной, и выученный десктопный селектор там ничего не найдёт. ☰ оглавление — **опциональная кнопка только по обучению**: эвристический поиск toc отключён (универсальной надёжной эвристики нет, ложная кнопка хуже отсутствия).
- **Прерванная работа продолжается, а не начинается заново** — фоновый перевод и прогресс NER пишутся в отдельную запись книги (`j/<ключ>` в IndexedDB сайта): чанки переводятся по одному, запись хранит уже готовые чанки, хэш исходного текста и число чанков. Ушёл на следующую главу во время перевода — вернувшись, видишь «▶️ Продолжаю фоновый перевод…» и докачиваются только недостающие чанки; сменился текст главы или число чанков — запись негодна, старт с чистого листа. Кнопка «🌐 Перевести заново» в меню ⋮ читалки — единственный способ начать заново осознанно (она сбрасывает запись). Завершённость ответа контролируется терминатором сервера: стрим считается полным только до `data: [DONE]` (или непустого `finish_reason` в последнем чанке); закрыли соединение без терминатора — это обрыв, чанк повторяется как сетевая ошибка. К пингу проверки сервера сторож не относится (он выходит на первом токене). Оборванный перевод больше не притворяется готовым: прогресс не прячется, в читалке остаётся «⏳ Перевод не завершён» с причиной, обычный запуск продолжит с сохранённого места.
- **Автоперевод следующей главы** (чекбокс «🚀 Автоперевод следующей главы в фоне», по умолчанию включён) — следующая глава скачивается и переводится в фоне (обычным запросом) и кладётся в кэш; уже закешированная пропускается, петля последней главы ничего не переводит. При открытии закешированной главы читалка сразу показывает готовый перевод («📖 Глава из кэша»). Кнопки ←/→ в читалке переходят по главам в пределах текущего сайта (гиперссылка только http(s); ссылка на чужой хост откроется новой вкладкой), и следующая глава сразу открывается в читалке (маркер автозапуска в sessionStorage); ☰ открывает оглавление в новой вкладке.
- **Данные книги — в IndexedDB её сайта** — глоссарии, отметки NER и кэш переводов живут в IndexedDB того сайта, где стоят книги: квота там — десятки процентов свободного диска; `localStorage` ограничен ~5 МБ на origin и мегабайтные глоссарии не влезает, а GM-хранилище расширения такой объём не тянет вовсе. В GM-хранилище — только список книг (метаданные) и настройки: они видны с любой страницы. Кэш переводов rolling-ный: текущая читаемая глава и следующая (не архив книги), порядок — по времени перевода; в кэш попадает только завершённый перевод — прерванный частичный при следующем открытии переводится заново. Кэш переживает перезапуск браузера. При переименовании книги (смене URL-ключа) записи сайта переносятся на новый ключ; удаление книги чистит и её данные на сайте. Важно: данные привязаны к сайту — очистка данных сайта в браузере удаляет глоссарий и кэш, а в приватном окне они живут до закрытия окна; глоссарий застрахован экспорт/импортом на вкладке Глоссарий.

- **Карточка книги** — вкладка «Книга» показывает статистику (термины, обработанные страницы, закешированные главы; для книг с других сайтов статистика нулевая — их данные живут на самих сайтах), поле обложки с кнопкой «🖼 Найти на странице» (сначала og:image, затем достаточно крупные картинки в контенте и в контейнерах с «cover» в классе/id; клик по кандидату выбирает его, битая ссылка скрывает предпросмотр) и кнопка «🔗 Открыть на сайте» — ведёт на адрес из записи книги: выученное оглавление, иначе последняя переведённая глава, при отсутствии переводов — URL книги.
- **Мобильная адаптация** — дизайн адаптируется CSS-медиазапросом `(max-width: 768px), (pointer: coarse)` внутри Shadow DOM (признак coarse ловит телефон даже в режиме «полной версии сайта», отдельного «мобильного режима» в JS нет): в читалке колонка становится почти на всю ширину с уменьшенными отступами, кнопки навигации — не ниже 44 px под палец, панели и плавающие кнопки учитывают safe-area (вырезы/жесты); модалка настроек — полноэкранная, табы прокручиваются горизонтально, таблица глоссария скроллится по горизонтали, форма добавления термина — в одну колонку, шрифт полей ввода 16 px (без авто-зума при фокусе), кнопки нижней панели читалки — компактнее и только иконками (подписи скрыты); окна обучения компактнее. В режиме обучения на телефоне работает отдельный touch-конвейер: отменяемый touchend подавляет синтетические клики и long-press-меню браузера (от тапов сайт не реагирует, ссылки не открываются), на время обучения включаются user-select:none и -webkit-touch-callout:none (нет выделения текста); одиночный тап только подсвечивает элемент, двойной тап по нему же или удержание ~0,5 с открывают попап типа, свайп остаётся прокруткой. На десктопе (одиночный клик мышью) поведение не меняется.
- **Поиск терминов — по канону конвейера** — термин ищется так же, как в `core/common.py`: NFC-нормализация, вычистка пробелов и пунктуации, затем containment по n-граммам (n=3) с проверкой по общей подпоследовательности. Поэтому термины находятся внутри китайского/японского/корейского предложения (где нет пробелов), в тайском, кхмерском и вьетнамском — старый вариант «граница слова обязательна» терял их систематически. — глобальный глоссарий убран: книга определяется по URL страницы (поддерживается ручная привязка), её глоссарий лежит в IndexedDB этого сайта. Вне страницы книги вкладка Глоссарий показывает подсказку, а не форму. Для каждой книги свой глоссарий (термин, перевод, тип, счётчик частоты). В перевод подставляются только релевантные термины (нечёткий поиск по n-граммам, порог настраивается).
- **URL книги — постоянная часть ссылки** — модал «Определение книги» объясняет суть и показывает примеры (royalroad `…/fiction/58180/название/chapter/982968/гл-1` → `…/fiction/58180/название`; 69shuba `…/txt/88724/41021619` → `…/txt/88724`; czbooks `…/n/cp61433/cpplpnhk?chapterNumber=3` → `…/n/cp61433/cpplpnhk`). Кнопка «🔍 Авто» чистит URL автоматически: отрезает всё от «маркерного» сегмента главы (`chapter|ch|c|p|page|volume|v|ep|episode|read|detail`), снимает хвостовой сегмент-число и выкидывает главные query-параметры (`?chapterNumber=3`, `?page=5`, …). Если книга заведена URL'ом одной главы, остальные главы всё равно распознаются как её страницы по общему родительскому каталогу (соседние главы).
- **Извлечение терминов (NER)** — LLM находит имена/места/артефакты/организации и пополняет глоссарий; повторное извлечение той же страницы пропускается (кэш, отключается). Дедупликация — точное совпадение, затем нечёткое; частоты суммируются. Ответ проверяется: допускается и чистый JSON-список, и одиночный объект, и обёртка `{"terms": [...]}`, и текст в ```json fences; запись без `term` или `translation` отбрасывается, `type` приводится, `aliases` сохраняются. Если разбор не удался или ответ пустой — чанк переспрашивается (до `NER_PARSE_ATTEMPTS` = 3 раз, на прогресс-баре этос оранжевыми полосами строка «⏱ … повтор N/3»), настоящие HTTP- и авторизационные ошибки не повторяются. Чанк, оставшийся без валидного ответа, помечается в статусе, страница не считается обработанной — её можно повторить отдельно. Ручное извлечение (пункт меню ⋮) идёт стримингом в маленьком плавающем окне с прогресс-баром и кнопкой «Отменить» — читалка при этом не открывается; ожидаемый размер ответа с терминами оценивается эвристически как ~2× размера исходного чанка, проценты считаются по символам, полученным от LLM. Отменённое извлечение сохраняет уже добавленные термины, но НЕ помечает страницу обработанной — при следующем запуске NER для неё выполнится заново.
- **Типы и пол — в формате конвейера** — пол живёт внутри поля `type`: `Person (male)`, `Creature (female)`, `Person (unknown)` (как в `ner.json` полного конвейера и `core/common.py::collect_gender_names`). Типы не захардкожены: поле ввода свободное с подсказками (datalist) из канонических примеров и типов, реально присутствующих в глоссарии.
- **Таймаут зависания в секундах** — `requestTimeout` в секундах (по умолчанию 60, 0 = без таймаута; старые значения-миллисекунды мигрируются автоматически). Дефолт поднят с 10 секунд: локальная модель отвечает на «Проверить сервер» дольше даже на хорошем канале. Для обычного запроса это общий лимит времени, для стриминга — пауза без полезных токенов: таймер передооружается только приходе контента, пустые SSE-пинги его не сбрасывают; сработал — запрос реально прерывается (гонка с abort-промисом, `reader.cancel()` и аварийный abort GM-запроса) и повторяется в пределах `maxRetries`; на прогресс-баре ретрай подсвечен оранжевыми полосами, незаконченный чанк переводится заново. Пустой ответ модели и ошибки API внутри SSE — фатальная ошибка на уровне запроса («Пустой ответ модели. Проверьте модель, права и параметры запроса.»), как и HTTP 4xx/5xx; при извлечении терминов такой чанк переспрачивается отдельным счётчиком. Отмена — кнопкой на панели прогресса.
- **Настройки** — API Host/Key/модель (совместимо с OpenAI `/chat/completions`), уровень reasoning (пусто или `None` — параметр не передаётся), таймаут и ретраи, размер чанка (`chunkSize`, СИМВОЛЫ), чекбокс автоперевода следующей главы, редактируемые промпты перевода и извлечения, внешность читалки. Плейсхолдеры промптов (`{sourceLang}`, `{targetLang}`, `{glossary}`, `{text}`) подставляются во всех вхождениях. **Настройки сохраняются автоматически при каждом изменении** — кнопки сохранения нет, есть только сброс к значениям по умолчанию.
- **«Локальная модель без API-ключа»** — чекбокс в секции API: пустой ключ разрешён, заголовок `Authorization` при этом не отправляется вовсе.
- **Запросы через `GM_xmlhttpRequest`** — обходят CORS и Mixed Content (http-API с https-страницы); при отсутствии `GM_xmlhttpRequest` — автоматический fallback на обычный `fetch`. Violentmonkey, в отличие от Tampermonkey, прав на запросы не спрашивает — они берутся из манифеста менеджера, так что окно разрешения при первом запросе появиться не должно и его отсутствие ни о чём не говорит. Менедеры отдают ответ по-разному: Tampermonkey умеет отдать `ReadableStream` (`responseType: 'stream'`), Violentmonkey сидит на XHR и поток не отдаёт вовсе. С 1.37 режим по умолчанию иной: запросы идут **fetch'ом прямо из страницы** (настройка «Сеть из страницы (fetch), канал менеджера — запасной», включена по умолчанию) — это не зависит от мостика контент↔фон, который у Violentmonkey на части устройств сломан (в трассе тогда висит только «rs1 +0б»); хост закрыт CORS — запрос автоматически повторяется каналом менеджера. Снимите галочку для старых порядков. Режим менеджера определяется по `GM_info.scriptHandler` и запоминается в GM-хранилище: у XHR-менеджера Lite сразу просит `text` (и его предупреждений в консоли больше нет) и наполняет собственный `ReadableStream` сам. Важно: Violentmonkey отдаёт тело **не целиком и не растущим `responseText`** — каждое событие (`readystatechange`/`progress`) приносит **очередной кусок**, нередко только в `response` (поле `responseText` в этот момент может не быть), а `load` приходит вообще с пустым телом. Поэтому Lite слушает `loadstart`/`progress`/`readystatechange`/`load`, читает кусок из `responseText` и из `response`, собирает их в один поток, а повтор того же куска (один и тот же `readyState` приходит дважды) отбрасывает. Старая схема «responseText всегда накопленный» под VM съедала только первый кусок: перевод обрывался на первом предложении, а остальное уходило в ретраи. Если на конкретном устройстве канал менеджера у Violentmonkey сломан совсем (в строке проверки висит только `rs1 +0б`, `/models` тоже молчит, хотя Tampermonkey в том же браузере летает) — в Настройках в блоке «🌐 Сеть» есть переключатель «Сеть из страницы (fetch), без канала менеджера»: запросы пойдут напрямую из страницы, минуя мостик контент↔фон. Нужен CORS-доступ хоста (у routerai — есть), иначе `fetch` падает мгновенно. Tampermonkey в таком переключателе не нуждается.
- **`@connect` выписан списком** — менеджер пользовательских скриптов проверяет домен запроса: Tampermonkey на это показывает диалог разрешения, а на мобильном Firefox диалог может не показаться вовсе, и запрос просто висит до таймаута. Поэтому типовые хосты объявлены явно — свои (`self`, `localhost`), российские роутеры моделей (`routerai.ru`, `routerapi.ru`, `zveno.ai`) и облака-провайдеры (OpenAI, OpenRouter, Anthropic, Google AI Studio, GitHub Models/Azure, Hugging Face, Groq, Together, Fireworks, DeepInfra, Cerebras, SambaNova, Mistral, xAI, Cohere, AI21, NVIDIA NIM, Replicate, DeepSeek, Moonshot, Zhipu, MiniMax, DashScope, Volcengine Ark, Qianfan, Hunyuan, StepFun, 01.AI, SiliconFlow, Novita, PPIO). `@connect *` оставлен последним — с ним у менеджера есть кнопка «Всегда разрешать для всех доменов»; сервер в локальной сети (`http://192.168.x.x:11434/v1`) всё равно придётся добавить в whitelist скрипта вручную.
- **Импорт/экспорт** — глоссария текущей книги и полного бэкапа: он включает настройки и список книг (метаданные), а глоссарии и кэши переводов сайтов резервируются экспорт/импортом глоссария на странице книги — их не перенести с одного origin на другой. Импорт глоссария принимает оба формата: канон `ner.json` конвейера (JSON-список записей, лишние поля проекта сохраняются) и старый экспорт Lite (JSON-объект; отдельное поле `gender` из старых версий мигрирует в `type`, enum-типы `character`/`location`/… нормализуются в `Person`/`Location`/…).
- UI — Shadow DOM (стили сайта не мешают): внизу справа **одна** плавающая кнопка ⋮, в покое полупрозрачная (0,55 — не мешает чтению), полный цвет при наведении или фокусе; в меню пять пунктов и именно в этом порядке: 🌐 перевести/читать, ✨ извлечь термины вручную, ➕ добавить книгу, 🎯 обучить элементам, ⚙️ настройки. На телефоне кнопка стала меньше (44×44 вместо 52×52), но осталась в пределах зоны касания. Тема по умолчанию — «🌗 как в системе»: Lite следует системной теме и переключается сразу, без перезагрузки страницы; кнопка 🌓 в меню ⋮ читалки ходит по кольцу «как в системе → тёмная → светлая» (текущий режим подписан в подсказке кнопки), тема читалки и UI одна. Верхняя панель читалки минимальна: ⋮ и ✕; все действия (экспорт TXT, перевод заново, тема, настройки) — в выпадающей панели ⋮, клик мимо неё закрывает. В глоссарии появился тумблер «только текущая страница»: показывает те термины книги, что реально встречаются на открытой странице (тот же матчинг, что при переводе), счётчик над списком становится вида `1/2`.

## Установка

1. Установите расширение **Tampermonkey** (Chrome/Firefox/Edge) или Violentmonkey.
   **Если под Violentmonkey скрипт «вообще ничего не делает»**, дело почти всегда не в скрипте: современный VM (MV3) внедряет скрипты через `chrome.userScripts`, и для него нужно включить разрешение расширения — `chrome://extensions` → «Violentmonkey» → «Подробности» → переключатель **«Разрешить пользовательские скрипты»** (Allow user scripts) → затем перезапустить браузер. Без него не появляется ни кнопка ⋮, ни окна установки: менеджер молча не инжектит скрипты.
2. Поставьте скрипт по ссылке — менеджер покажет окно установки и в дальнейшем сам будет его обновлять:
   - `https://raw.githubusercontent.com/LynxPDA/NovelMaestro/main/tools/NovelMaestro_Lite/novelmaestro-lite.user.js` — основной путь: raw отдаёт свежее содержимое за минуты;
   - `https://cdn.jsdelivr.net/gh/LynxPDA/NovelMaestro@main/tools/NovelMaestro_Lite/novelmaestro-lite.user.js` — зеркало (MIME `application/javascript`), если raw недоступен; файлы ветки на CDN кэшируются на неделю, и новый коммит кэш не снимает — проверять обновления по нему нельзя.
3. Или вручную: панель расширения → «Создать новый скрипт» → вставить содержимое `tools/NovelMaestro_Lite/novelmaestro-lite.user.js` целиком → сохранить (Ctrl+S). Обновления после этого приходят по `@updateURL` из блока метаданных (он указывает на `novelmaestro-lite.meta.js`), но ставить скрипт ссылкой надёжнее.
4. Откройте любую страницу — внизу справа появится полупрозрачная кнопка ⋮ (в нём перевод, термины, книга, обучение и настройки).
5. **Разрешения на запросы к API**: баннер объявляет `@connect` списком популярных доменов, так что для них диалог не появляется. Если ваш хост в списке отсутствует, Tampermonkey спросит разрешение при первом запросе — ответьте «Всегда разрешать для домена» (или «Всегда разрешать для всех доменов» — `@connect *` для этой кнопки и оставлен). Если окно уже отклоняли или запросы молча не доходят (мгновенное «Некорректный ответ API»/«Failed to fetch»), откройте панель Tampermonkey → настройки скрипта NovelMaestro Lite → секция **«Безопасность XHR»** (`XHR Security`/«Безопасность»): добавьте домен API-хоста в список разрешённых (или выберите «Разрешить все домены» — скрипт объявляет `@connect *`). Без этого разрешения `GM_xmlhttpRequest` не выполнится и перевод работать не будет.

## Первый запуск

1. ⋮ → **Настройки** → укажите **API Host** и **модель** (для локального сервера без ключа включите «Локальная модель без API-ключа»), затем «🔌 Проверить сервер». Проверка сначала шлёт короткий `POST /chat/completions` стримом с `max_tokens: 1` — ровно тот запрос, которым идёт перевод, — и отвечает одной строкой с адресом, временем и транспортом; результат готов по первому токену, а соединение Lite закрывает сам (серверы, отвечающие SSE и не закрывающие его вовремя, больше не заставляют проверку висеть до таймаута): `✅ Сервер доступен • routerai.ru/api/v1 • пинг 907мс • модель google/gemma-4-31b-it • ответ: пинг • менеджер · XHR (тело целиком)`. Тяжёлый `GET /models` (у routerai.ru это 528 моделей и ~876КБ) отдельно НЕ запрашивается: на мобильном канале он не успевает даже за минуту. Он включается только как диагноз, если пинг не дошёл, — со своим запасом в 60с, и тогда строка говорит, есть ли канал вообще и есть ли нужная модель в списке. Ваш `requestTimeout` при этом не подменяется: он относится к запросам перевода. Скрипт работает с любым OpenAI-совместимым сервером (в т.ч. тем же, что настроен в системном `.env` NovelMaestro). Настройки сохраняются сами — достаточно поменять поле.
2. Откройте страницу главы: ⋮ → «🌐 Перевести / читать» (книгу можно сразу завести через «➕ Добавить книгу») — при непривязанном URL откроется модал «Определение книги»: укажите постоянную часть URL («Авто» подставит) и название, сохраните.
3. Первый 🌐 на книге без обученных элементов откроет **обучение**: наведите курсор на блок текста главы, кликните и выберите «📄 Блок основного текста»; при желании так же назначьте кнопки ←/→ и оглавление — или пропустите (тогда навигация будет искаться эвристикой). «✅ Готово» — и перевод стартует сам: термины сначала извлекутся в глоссарий (один раз на страницу), затем глава переводится по чанкам со стримингом прямо в читалке.
4. Чтение: ←/→ переключают главы (следующая сразу открывается в читалке), ☰ открывает оглавление, сверху — ⋮ меню (📄 экспорт TXT текущей главы, 🌐 перевести заново без кэша, 🌓 тема, ⚙️ настройки) и ✕ закрыть. При включённом опережающем переводе следующая глава переводится в фоне и открывается мгновенно.
5. Глоссарий: вкладка **Глоссарий** на странице книги — добавление, правка, фильтр, сортировка по любому полю, пагинация, импорт/экспорт, очистить (глоссарий + кэш извлечения книги). Глоссарий у каждой книги свой; вне страницы книги вкладка показывает подсказку.

## Формат глоссария

JSON-объект «идентификатор → запись», совместимый по полям записей с `ner.json` проекта NovelMaestro (у конвейера файл — JSON-список, при импорте в Lite он разворачивается в объект): пол указывается внутри `type` в скобках — `Person (male)`, `Person (female)`, `Person (unknown)`; для не-персонажей пол не указывается:

```json
{
  "ид_термина": {
    "term": "林浩",
    "translation": "Линь Хао",
    "type": "Person (male)",
    "count": 12
  }
}
```

Экспорт (кнопка «📤 Экспорт») выгружает глоссарий в JSON-список записей — тот же формат, что и `ner.json` конвейера, поэтому файл можно переименовать и положить в проект как есть.

Миграция: записи старых версий Lite с отдельным полем `gender` (`male`/`female`/`neutral`/`null`) автоматически конвертируются в `type` при загрузке скрипта и при импорте; `character` → `Person`, `location` → `Location` и т.д.

## Отличие от полного конвейера

NovelMaestro Lite — про «прочитать главу прямо сейчас»: переводы и глоссарии живут в IndexedDB браузера каждого сайта книги (мгновенное открытие кэшированной главы, экспорт TXT текущей страницы), но в файлы проекта конвейера ничего не сохраняется. Полный конвейер (epub → ner → ner_check → pipeline → translate_check → compile → wiki) — в web-интерфейсе проекта. Глоссарий Lite экспортируется в JSON и совместим по формату записей с `ner.json`, поэтому накопленное можно переносить в проект.

## Безопасность

- API Key хранится только в хранилище расширения (`GM_setValue`) и отправляется лишь на указанный API Host. Скрипт запрашивает `@match *://*/*` (универсальный переводчик) и `@connect *` (запросы к любому LLM-серверу; конкретные домены разрешаются в секции «Безопасность XHR» настроек скрипта в Tampermonkey) — при желании сузьте оба списка в метаданных до сайтов и хостов, которыми пользуетесь.
- `@noframes`: скрипт работает только в верхнем документе. Проверено на живых страницах (69shuba, RoyalRoad, czbooks, tl.rulate.ru) — текст главы везде лежит в верхнем документе, а без `@noframes` Lite дополнительно поднималась и в сторонних фреймах: там тоже создавались теневой хост и набор плавающих кнопок (на RoyalRoad таких фреймов три). Если тебе попадётся сайт, где глава отдаётся из внутристраничного iframe, убери эту строку из `meta.js` и пересобери.
- Полный бэкап (`novelmaestro-backup-*.json`) содержит API Key — не публикуйте его.

## Исходники и сборка

Скрипт распространяется одним файлом, но разрабатывается частями: `src/NNN-*.js` лежат уже на финальном отступе внутри IIFE-обёртки (её открывающая и закрывающая строки — `src/000-open.js` и `src/900-close.js`), баннер метаданных — `meta.js`, он же единственный источник `@version` (в теле — токен `{{VERSION}}`). Сборщик `tools/build_userscripts.py` их просто склеивает: баннер, пустая строка, части в порядке имён — без переотступов, переносов и минификации, поэтому собранный файл побайтово равен тому, что было бы написано руками. Кроме `novelmaestro-lite.user.js` сборщик пишет `novelmaestro-lite.meta.js` — файл проверки обновлений (тот же блок метаданных без тела); оба собранных файла руками не правятся.

Нумерация `NNN` с шагом 10 (010, 020, 030 …): новая часть вставляется файлом `025-*.js` — переименовывать хвост не нужно. Крупная часть со временем режется на две-три новыми файлами с соседними номерами, порядок склейки не меняется.

Порядок частей — порядок секций исходного файла, и он функциональный: `080-ui-markup.js` создаёт DOM-ссылки, на которые смотрит остальной UI, а `200-events.js` и `210-init.js` исполняются сразу при загрузке страницы.
