# NovelMaestro Lite — юзерскрипт-читалка

Лёгкий браузерный аналог конвейера NovelMaestro: юзерскрипт для Tampermonkey/Violentmonkey, который переводит веб-новеллы (и вообще любые сайты) на русский язык через OpenAI-совместимые LLM-серверы — прямо в браузере, без сервера и установки проекта. Основной режим — **читалка**: полноэкранное окно чтения, где текст главы заменён переводом. Глоссарий терминов ведётся по книгам, извлечение терминов (NER) и перевод — со стримингом.

Файл: `NovelMaestro_Lite_tampermonkey.js` (версия — в метаданных файла).

## Возможности

- **Режим читалки** — по кнопке 🌐 страница заменяется полноэкранным режимом чтения: верхняя панель (название главы, 🌓 тема, ⚙️ настройки, ✕ закрыть), текст главы с абзацами, нижняя панель (🌐 перевести заново без кэша, ← предыдущая, ☰ оглавление, → следующая, статус опережающего перевода). Перевод приходит стримингом прямо в читалку с прогресс-баром по абзацам. Внешний вид настраивается: тема (светлая «бумага»/тёмная, она же для всего UI), шрифт (Georgia/Arial/Times New Roman/Verdana/Segoe UI), размер (px, по умолчанию 14), межстрочный интервал, отступ между абзацами (em), ширина колонки — в **процентах ширины экрана** (настройка, по умолчанию 80; старые значения — пиксельные и 66% — мигрируются автоматически).
- **Обучение элементам для книги (как в uBlock Origin)** — режим из меню ⋮: наводишь курсор — элемент подсвечивается, клик — попап выбирает тип: 📄 блок основного текста (обязателен), ← «Назад», → «Вперёд», ☰ «Оглавление» (необязательные). Вместо хрупких уникальных селекторов сохраняется **сигнатура элемента**: тег, id/классы и цепочка до четырёх предков — на других главах той же книги элемент находится по структуре страницы (обучение — эвристика на всю книгу). При первом 🌐 на необученной книге обучение открывается само; после «✅ Готово» перевод стартует автоматически.
- **Навигация по главам** — ←/→ сначала ищутся по выученным сигнатурам, затем фолбэком по всей странице: `rel="next|prev"`, текст/класс/id ссылки (next/previous/вперёд/назад/след, китайские 下一章/下一页 и вьетнамские Chương trước/sau/tiếp theo), одиночная ссылка в контейнере. Это важно именно на телефоне: мобильная версия сайта часто отличается по структуре от десктопной, и выученный десктопный селектор там ничего не найдёт. ☰ оглавление — **опциональная кнопка только по обучению**: эвристический поиск toc отключён (универсальной надёжной эвристики нет, ложная кнопка хуже отсутствия).
- **Автоперевод следующих глав** (настройка «🚀 Автоперевод следующих глав», по умолчанию 1) — 0 — переводить только текущую главу; 1 — следующая скачивается и переводится в фоне (обычным запросом) и кладётся в кэш; N — цепочкой следующие N глав подряд (уже закешированные проходятся транзитом, петля последней главы цепочку останавливает). При открытии закешированной главы читалка сразу показывает готовый перевод («📖 Глава из кэша»). Кнопки ←/→ в читалке переходят по главам в пределах текущего сайта (гиперссылка только http(s); ссылка на чужой хост откроется новой вкладкой), и следующая глава сразу открывается в читалке (маркер автозапуска в sessionStorage); ☰ открывает оглавление в новой вкладке.
- **Кэш глав (персистентный)** — переводы живут в `localStorage` под URL главы (вместе с названием и найденной навигацией), индекс по книгам хранит главы в порядке добавления; в кэш попадает только завершённый перевод — прерванный или отменённый частичный при следующем открытии переводится заново. Настройка «Кэш переведённых глав»: по умолчанию последние 10 (при переполнении вытесняются самые старые), 0 = не сохранять, -1 = без ограничений; кэш переживает перезапуск браузера. Удаление книги очищает её кэш; при переименовании книги (смене URL-ключа) кэш переносится на новый ключ.
- **Офлайн-чтение** — кнопка «📖 Читать из кэша» на вкладке Книга открывает читалку по закешированным главам, **выстроенным в порядке чтения**: порядок восстанавливается цепочкой из сохранённых prev/next (главы, переведённые вразноброс, выложатся по порядку; несвязанные цепочки дописываются по времени, петли обрываются). Статусная строка «📴 Оффлайн • глава N из M», ←/→ листают соседей по цепочке, повторный перевод скрыт — сеть не нужна; ☰ открывает список переведённых глав (нумерация, названия, текущая выделена, нажатие переносит на главу).
- **Карточка книги** — вкладка «Книга» показывает статистику (термины, обработанные страницы, закешированные главы), поле обложки с кнопкой «🖼 Найти на странице» (сначала og:image, затем достаточно крупные картинки в контенте и в контейнерах с «cover» в классе/id; клик по кандидату выбирает его, битая ссылка скрывает предпросмотр) и кнопки «📖 Читать из кэша», «📄 Экспорт TXT» (одним файлом, по порядку следования глав, с названиями) и «🔗 Открыть на сайте» — ведёт на оглавление, если оно обучено (tocUrl есть в кэшированных главах), иначе на последнюю по времени переводa главу, и лишь при пустом кэше — на URL книги.
- **Мобильная адаптация** — дизайн адаптируется CSS-медиазапросом `(max-width: 768px), (pointer: coarse)` внутри Shadow DOM (признак coarse ловит телефон даже в режиме «полной версии сайта», отдельного «мобильного режима» в JS нет): в читалке колонка становится почти на всю ширину с уменьшенными отступами, кнопки навигации — не ниже 44 px под палец, панели и плавающие кнопки учитывают safe-area (вырезы/жесты); модалка настроек — полноэкранная, табы прокручиваются горизонтально, таблица глоссария скроллится по горизонтали, форма добавления термина — в одну колонку, шрифт полей ввода 16 px (без авто-зума при фокусе), кнопки нижней панели читалки — компактнее и только иконками (подписи скрыты); окна обучения компактнее. В режиме обучения на телефоне работает отдельный touch-конвейер: отменяемый touchend подавляет синтетические клики и long-press-меню браузера (от тапов сайт не реагирует, ссылки не открываются), на время обучения включаются user-select:none и -webkit-touch-callout:none (нет выделения текста); одиночный тап только подсвечивает элемент, двойной тап по нему же или удержание ~0,5 с открывают попап типа, свайп остаётся прокруткой. На десктопе (одиночный клик мышью) поведение не меняется.
- **Глоссарий по книгам** — книга определяется по URL (поддерживается ручная привязка страницы к книге). Для каждой книги свой глоссарий (термин, перевод, тип, счётчик частоты), плюс отдельный **глобальный глоссарий**. В перевод подставляются только релевантные термины (нечёткий поиск по n-граммам, порог настраивается).
- **URL книги — постоянная часть ссылки** — модал «Определение книги» объясняет суть и показывает примеры (royalroad `…/fiction/58180/название/chapter/982968/гл-1` → `…/fiction/58180/название`; 69shuba `…/txt/88724/41021619` → `…/txt/88724`; czbooks `…/n/cp61433/cpplpnhk?chapterNumber=3` → `…/n/cp61433/cpplpnhk`). Кнопка «🔍 Авто» чистит URL автоматически: отрезает всё от «маркерного» сегмента главы (`chapter|ch|c|p|page|volume|v|ep|episode|read|detail`), снимает хвостовой сегмент-число и выкидывает главные query-параметры (`?chapterNumber=3`, `?page=5`, …). Если книга заведена URL'ом одной главы, остальные главы всё равно распознаются как её страницы по общему родительскому каталогу (соседние главы); ранние «осиротевшие» кэшированные переводы (записанные до распознавания) привязываются к книге при старте скрипта.
- **Извлечение терминов (NER)** — LLM находит имена/места/артефакты/организации и пополняет глоссарий; повторное извлечение той же страницы пропускается (кэш, отключается). Дедупликация — точное совпадение, затем нечёткое; частоты суммируются. Ручное извлечение (пункт меню ⋮) идёт стримингом в маленьком плавающем окне с прогресс-баром и кнопкой «Отменить» — читалка при этом не открывается; ожидаемый размер ответа с терминами оценивается эвристически как ~2× размера исходного чанка, проценты считаются по символам, полученным от LLM. Отменённое извлечение сохраняет уже добавленные термины, но НЕ помечает страницу обработанной — при следующем запуске NER для неё выполнится заново.
- **Типы и пол — в формате конвейера** — пол живёт внутри поля `type`: `Person (male)`, `Creature (female)`, `Person (unknown)` (как в `ner.json` полного конвейера и `core/common.py::collect_gender_names`). Типы не захардкожены: поле ввода свободное с подсказками (datalist) из канонических примеров и типов, реально присутствующих в глоссарии.
- **Таймаут зависания в секундах** — `requestTimeout` в секундах (по умолчанию 10, 0 = без таймаута; старые значения-миллисекунды мигрируются автоматически). Для обычного запроса это общий лимит времени, для стриминга — пауза без полезных токенов: таймер передооружается только приходе контента, пустые SSE-пинги его не сбрасывают; сработал — запрос реально прерывается (гонка с abort-промисом, `reader.cancel()` и аварийный abort GM-запроса) и повторяется в пределах `maxRetries`; на прогресс-баре ретрай подсвечен оранжевыми полосами, незаконченный чанк переводится заново. Пустой ответ модели и ошибки API внутри SSE — фатальная ошибка («Пустой ответ модели. Проверьте модель, права и параметры запроса.»), как и HTTP 4xx/5xx, она не ретраится. Отмена — кнопкой на панели прогресса.
- **Настройки** — API Host/Key/модель (совместимо с OpenAI `/chat/completions`), уровень reasoning (пусто или `None` — параметр не передаётся), таймаут и ретраи, размер чанка (`chunkSize`, СИМВОЛЫ), источник глоссария при переводе, редактируемые промпты перевода и извлечения, автоперевод следующих глав (0–20), внешность читалки. Плейсхолдеры промптов (`{sourceLang}`, `{targetLang}`, `{glossary}`, `{text}`) подставляются во всех вхождениях. **Настройки сохраняются автоматически при каждом изменении** — кнопки сохранения нет, есть только сброс к значениям по умолчанию.
- **«Локальная модель без API-ключа»** — чекбокс в секции API: пустой ключ разрешён, заголовок `Authorization` при этом не отправляется вовсе.
- **Запросы через `GM_xmlhttpRequest`** — обходят CORS и Mixed Content (http-API с https-страницы); при отсутствии `GM_xmlhttpRequest` — автоматический fallback на обычный `fetch`. Если менеджер скриптов не поддерживает стриминговый `responseType`, ответ приходит целиком и обрабатывается как один кусок потока. «Проверить сервер» показывает текст ошибки API, а не безымянное «Некорректный ответ API».
- **Импорт/экспорт** — глоссария и полного бэкапа всех данных (книги, глоссарии, кэш NER, настройки) — для переноса на другой компьютер. Импорт принимает оба формата: канон `ner.json` конвейера (JSON-список записей, лишние поля проекта сохраняются) и старый экспорт Lite (JSON-объект; отдельное поле `gender` из старых версий мигрирует в `type`, enum-типы `character`/`location`/… нормализуются в `Person`/`Location`/…).
- UI — Shadow DOM (стили сайта не мешают): внизу справа две плавающие кнопки — 🌐 (перевести/читалка) и ⋮ (меню: ⚙️ настройки, ✨ извлечь термины вручную, 🎯 обучить элементам, 🌓 тема). Тёмная тема читалки переключает и тему UI.

## Установка

1. Установите расширение **Tampermonkey** (Chrome/Firefox/Edge) или Violentmonkey.
2. Откройте панель расширения → «Создать новый скрипт».
3. Вставьте содержимое `tools/NovelMaestro_Lite/NovelMaestro_Lite_tampermonkey.js` целиком и сохраните (Ctrl+S).
4. Откройте любую страницу — внизу справа появятся кнопки 🌐 (перевести/читалка) и ⋮ (меню).
5. **Разрешения на запросы к API (Tampermonkey)**: при первом запросе Tampermonkey спросит, разрешить ли междоменный запрос к домену вашего LLM-сервера — ответьте «Разрешить всегда». Если окно уже отклоняли или запросы молча не доходят (мгновенное «Некорректный ответ API»/«Failed to fetch»), откройте панель Tampermonkey → настройки скрипта NovelMaestro Lite → секция **«Безопасность XHR»** (`XHR Security`/«Безопасность»): добавьте домен API-хоста в список разрешённых (или выберите «Разрешить все домены» — скрипт объявляет `@connect *`). Без этого разрешения `GM_xmlhttpRequest` не выполнится и перевод работать не будет.

## Первый запуск

1. ⋮ → **Настройки** → укажите **API Host** и **модель** (для локального сервера без ключа включите «Локальная модель без API-ключа»); «Проверить сервер» покажет доступность и пинг. Скрипт работает с любым OpenAI-совместимым сервером (в т.ч. тем же, что настроен в системном `.env` NovelMaestro). Настройки сохраняются сами — достаточно поменять поле.
2. Откройте страницу главы и нажмите 🌐 — при непривязанном URL откроется модал «Определение книги»: укажите постоянную часть URL («Авто» подставит) и название, сохраните.
3. Первый 🌐 на книге без обученных элементов откроет **обучение**: наведите курсор на блок текста главы, кликните и выберите «📄 Блок основного текста»; при желании так же назначьте кнопки ←/→ и оглавление — или пропустите (тогда навигация будет искаться эвристикой). «✅ Готово» — и перевод стартует сам: термины сначала извлекутся в глоссарий (один раз на страницу), затем глава переводится по чанкам со стримингом прямо в читалке.
4. Чтение: ←/→ переключают главы (следующая сразу открывается в читалке), ☰ открывает оглавление, 🌐 внизу — перевести заново без кэша. При включённом опережающем переводе следующая глава переводится в фоне и открывается мгновенно.
5. Глоссарий: вкладка **Глоссарий** — добавление, правка, фильтр, сортировка по любому полю, пагинация, импорт/экспорт, очистить (глоссарий + кэш извлечения книги). Переключатель «Работать с» выбирает глобальный глоссарий или глоссарий конкретной книги.

## Формат глоссария

JSON-объект «идентификатор → запись», совместимый по полям записей с `ner.json` проекта NovelMaestro (у конвейера файл — JSON-список, при импорте в Lite он разворачивается в объект): пол указывается внутри `type` в скобках — `Person (male)`, `Person (female)`, `Person (unknown)`; для не-персонажей пол не указывается:

```json
{
  "ид_термина": {
    "term": "林浩",
    "translation": "Линь Хао",
    "type": "Person (male)",
    "count": 12
  }
}
```

Экспорт (кнопка «📤 Экспорт») выгружает глоссарий в JSON-список записей — тот же формат, что и `ner.json` конвейера, поэтому файл можно переименовать и положить в проект как есть.

Миграция: записи старых версий Lite с отдельным полем `gender` (`male`/`female`/`neutral`/`null`) автоматически конвертируются в `type` при загрузке скрипта и при импорте; `character` → `Person`, `location` → `Location` и т.д.

## Отличие от полного конвейера

NovelMaestro Lite — про «прочитать главу прямо сейчас»: перевод живёт в читалке и localStorage браузера (персистентный кэш глав, офлайн-чтение и экспорт TXT), но в файлы проекта конвейера ничего не сохраняется. Полный конвейер (epub → ner → ner_check → pipeline → translate_check → compile → wiki) — в web-интерфейсе проекта. Глоссарий Lite экспортируется в JSON и совместим по формату записей с `ner.json`, поэтому накопленное можно переносить в проект.

## Безопасность

- API Key хранится только в хранилище расширения (`GM_setValue`) и отправляется лишь на указанный API Host. Скрипт запрашивает `@match *://*/*` (универсальный переводчик) и `@connect *` (запросы к любому LLM-серверу; конкретные домены разрешаются в секции «Безопасность XHR» настроек скрипта в Tampermonkey) — при желании сузьте оба списка в метаданных до сайтов и хостов, которыми пользуетесь.
- Полный бэкап (`novelmaestro-backup-*.json`) содержит API Key — не публикуйте его.
