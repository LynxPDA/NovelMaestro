## 1. Раскладка и сборка

- `meta.js` — баннер юзерскрипта, **единственный источник `@version`** (в теле — токен `{{VERSION}}`); `src/NNN-slug.js` — части, уже на финальном отступе внутри IIFE (000-open.js/900-close.js — сама обёртка); `novelmaestro-lite.user.js` и `.meta.js` — публикуемые артефакты, **руками не правятся** (перезапишет сборка).
- Порядок частей = порядок секций, менять нельзя; нумерация с шагом 10 (вставка части — новый `025-*.js`, а не переименование хвоста). Только LF; сборщик — сознательно тупая конкатенация без переотступов и минификации.


## 2. Тестирование Lite

- **Достаточная офлайн-проверка** — только юзерскрипты, ~1 с: `python3 -m pytest tests/test_tools_userscripts.py -q` (из корня репо). Она сторожит главное: артефакт побайтово == сборка, порядок и имена частей, канон метаданных, блок `@connect`, инварианты раскладки Lite (топбар читалки ⋮+✕, порядок панели ⋮, отсутствие «Экспорт TXT» в карточке книги, тумблер «только текущая страница», дефолты `gmTransport: 'page'` / `glossaryCurrentPageOnly: false`, наличие сторожа `[DONE]`).
- Полный `python3 -m pytest tests/ -q` (~3 мин) — входной гейт перед коммитом по корневому AGENTS, а не рабочий инструмент каждой правки; для ветки Lite достаточно точечного файла, полный прогон — на входе.
- Тесты **не ходят в сеть**: LLM только мокать/локальный сервер; данные — tmp. Никаких npm/node-сборок: node используется только как `node --check`.

### Живые полигоны (все временные, в git не коммитить)

Скрипты лежат в `/tmp/nm_probe/`, серверы — локальные (`127.0.0.1:8966/8971/8972`), LLM — фейковый стрим-сервер, ставящий `access-control-allow-origin: *` и **закрывающий поток с `data: [DONE]`**. Артефакт подменяется переменной `LITE_SCRIPT` (текущий или старый для A/B: `git show <commit>:tools/NovelMaestro_Lite/novelmaestro-lite.user.js > /tmp/nm_probe/lite-prev.user.js`).

| полигон | что проверяет |
| --- | --- |
| `check.mjs <сценарий>` | проверка сервера; сценарии `ok15` `dead` `alldead` `heavy` `ssehanging` (SSE держат открытым — пинг обязан выйти по первому токену) |
| `vm9.mjs` | полный путь Lite под настоящим VM 2.49 в Chromium: обучение → NER → читалка |
| `gd.mjs` | поднять Firefox (geckodriver/WebDriver) и временно поставить VM 2.49 (`vm.xpi`) |
| `ffrun2.mjs` | Firefox+VM: установка скрипта через страницу подтверждения и «🔌 Проверить сервер» |
| `flowff.mjs` | Firefox+VM полный путь: книга → обучение → NER → перевод → топбар/панель ⋮/экспорт TXT → глоссарий-тумблер |
| `theme.mjs`, `reader.mjs`, `localvm.mjs`, `probe*.mjs` | прежние точечные прогонки (тема, читалка, транспорты) |

- Хром: у VM (MV3) внедрение скриптов требует переключателя **«Разрешить пользовательские скрипты»** на странице расширения; без него кажется, что «Tampermonkey работает, Violentmonkey нет».
- Firefox: VM ставится временным аддоном (`/session/<id>/moz/addon/install`, `temporary: true`); навигацию на `.user.js` делать из JS (`location.href=…`), иначе WebDriver блокируется загрузкой; установка — кнопка `Install` на moz-extension-странице подтверждения.
- **Питомцы для граблей:** длительные прогоны запускать обёрткой `nohup bash runX.sh &` (log в `/tmp/nm_probe/*.log`); убивать только `pkill -x geckodriver` — `pkill -f <имя скрипта>` матчит собственную оболочку команды и убивает её саму.
- Tampermonkey локально не поднимается (нет офлайн-пакета) — его ветка проверяется на устройстве пользователя; локально строгая среда — VM (текстовый XHR-транспорт).

## 3. Транспорт Lite — что нельзя ломать

- Режим по умолчанию `gmTransport: 'page'`: запросы идут `fetch` из страницы (не зависят от мостика контент↔фон, у Violentmonkey на части устройств он сломан — тогда в трассе только `rs1 +0б`); при сетевой ошибке тот же запрос один раз уходит каналом менеджера (`gmFetch`). `'manager'` — старые порядки.
- Менеджеры разные: **Tampermonkey** отдаёт `responseType:'stream'` (токены потоком), **Violentmonkey** — XHR, тело приходит **кусками** (каждое событие несёт очередной кусок, нередко только в `response`, `load` — пустой;chunks собраны `absorb()`+`lastPiece`). Режим запоминается по `GM_info.scriptHandler` (`gmStreamMode`), а не первым ответом.
- Пинг «Проверить сервер» — стрим с `stopOnFirstContent`+`deadline`: выходит по первому токену и сам abort'ит соединение; `requestTimeout` для него — общий дедлайн, для переводостримов в текстовом режиме менеджер не участвует в таймере.
- Сторож завершённости (`[DONE]`/finish_reason) стоит **после** раннего выхода пинга и ветки пустого ответа: неполный стрим перевода — retryable «обрыв ответа…», частичный остаётся в фоновом задании (`j/<ключ>` в IndexedDB) для продолжения; в кэш глав попадает только завершённый перевод.

## 4. Из корневого AGENTS.md (релевантное Lite)

- Стиль: русский в строках/логах/UI; комментарии — только «почему», без комментариев-дневников (номера сессий/раундов — в TODO.md); компактные функции.
- Единицы: размеры чанков/бюджеты — **СИМВОЛЫ**; `max_tokens` — токены; `requestTimeout` — **секунды**; не путать.
- JSON-файлы данных (экспорт/импорт глоссария и т.п.): имена полей — английский (`term`, `translation`, `type`, `count`, `status`, …), значения и тексты — русские.
- Unicode: везде, где сравнивается/заменяется русский текст, — NFC; кавычки «»"" и тире —–- считать разными.
- Regexp-поля — чистый `re` Python-семантики без кастомных флагов (в Lite — свои JS-флаги, комментариев в полях тоже нет).
- Commits: conventional, атомарные, на русском (`fix(tools): Lite — …`); отметил задачу — обнови статус в корневом `TODO.md` в том же коммите; запушено обязательно. Незапушенный коммит — не завершённая работа.
- Запреты: не трогать боевой Docker-контейнер и его данные; эксперименты с книгами — только временные данные (`/tmp`, tmp_path); `dist/`, `projects/`, `servers/`, `Images/`, `backup/`, корневой `.env` в git не попадают.
