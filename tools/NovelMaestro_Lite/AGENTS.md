- `meta.js` — баннер юзерскрипта, **единственный источник `@version`** (в теле — токен `{{VERSION}}`); `src/NNN-slug.js` — части, уже на финальном отступе внутри IIFE (000-open.js/900-close.js — сама обёртка); `novelmaestro-lite.user.js` и `.meta.js` — публикуемые артефакты, **руками не правятся** (перезапишет сборка).
- Порядок частей = порядок секций, менять нельзя; нумерация с шагом 10 (вставка части — новый `025-*.js`, а не переименование хвоста). Только LF; сборщик — сознательно тупая конкатенация без переотступов и минификации.

## 2. Тестирование Lite

- **Достаточная офлайн-проверка** — только юзерскрипты, ~1 с: `python3 -m pytest tests/test_tools_userscripts.py -q` (из корня репо). Она сторожит главное: артефакт побайтово == сборка, порядок и имена частей, канон метаданных, блок `@connect`, инварианты раскладки Lite (топбар читалки ⋮+✕, порядок панели ⋮, отсутствие «Экспорт TXT» в карточке книги, тумблер «только текущая страница», дефолты `gmTransport: 'page'` / `glossaryCurrentPageOnly: false`, наличие сторожа `[DONE]`), а также `node --test tests/tools/*.test.mjs` — чистая логика Lite: какие reasoning/thinking-ключи уходят в тело запроса, финальное состояние панели прогресса, жизнь флага отмены и валидация полей настроек (`parseNumSetting` по маркерам + сверка границ `min`/`max` из разметки со спецификациями парсеров). Части — один IIFE (DOM и `GM_*` в node не работают), поэтому тест вырезает подопытный блок из артефакта по маркерам и исполняет его как чистую функцию.
- **Линт по одной части всегда даёт ложные «never used»** (`callLLM`, `checkServer`, `normalizeEffort`): их вызывают соседи по IIFE. Снимать через `lens_diagnostic_mark` false-positive, а не «удалять неиспользуемое».
- Полный прогон — `./dev.sh test` (это `python3 -m pytest tests/ -q -n auto`, pytest-xdist; весь набор — единицы секунд). Входной гейт перед коммитом по корневому AGENTS, а не рабочий инструмент каждой правки: для ветки Lite достаточно точечного файла, полный прогон — на входе. Раннер один — pytest: параллельность даёт плагин xdist (`-n auto` по умолчанию), второй тест-фреймворк или «свой раннер» не появлялись и не появятся; `python3 -m pytest tests/ -q` без `-n` — только для отладки одного теста.
- Тесты **не ходят в сеть**: LLM только мокать/локальный сервер; данные — tmp. Никаких npm/node-сборок: node используется только как `node --check` и `node --test`.

## 3. Транспорт Lite — что нельзя ломать

- Режим по умолчанию `gmTransport: 'page'`: запросы идут `fetch` из страницы (не зависят от мостика контент↔фон, у Violentmonkey на части устройств он сломан — тогда в трассе только `rs1 +0б`); при сетевой ошибке тот же запрос один раз уходит каналом менеджера (`gmFetch`). `'manager'` — старые порядки.
- Менеджеры разные: **Tampermonkey** отдаёт `responseType:'stream'` (токены потоком), **Violentmonkey** — XHR, тело приходит **кусками** (каждое событие несёт очередной кусок, нередко только в `response`, `load` — пустой;chunks собраны `absorb()`+`lastPiece`). Режим запоминается по `GM_info.scriptHandler` (`gmStreamMode`), а не первым ответом.
- Пинг «Проверить сервер» — стрим с `stopOnFirstContent`+`deadline`: выходит по первому токену и сам abort'ит соединение; `requestTimeout` для него — общий дедлайн, для переводостримов в текстовом режиме менеджер не участвует в таймере.
- Сторож завершённости (`[DONE]`/finish_reason) стоит **после** раннего выхода пинга и ветки пустого ответа: неполный стрим перевода — retryable «обрыв ответа…», частичный остаётся в фоновом задании (`j/<ключ>` в IndexedDB) для продолжения; в кэш глав попадает только завершённый перевод.
- **Флаг отмены живёт ровно один прогон**: `cancelRequested = false` и `activeReader = null` сбрасываются в `finally` И `runTranslationFlow`, И `handleExtractTerms`. Взведённый после отмены флаг валил каждый следующий запрос мгновенным «Отменено пользователем (0мс)» — и «Проверить сервер», и перевод; лечилось только перезагрузкой страницы.
- **Панель прогресса имеет два состояния** (`progressState`): работа — кнопка «Отменить», итог — кнопка «Скрыть» (`#reader-progress-close`). Готовая глава и явная отмена гасят панель сами (2,5 с / 3 с), оборванный перевод остаётся перед глазами, но закрывается одним нажатием.
- **Размышления thinking-моделей** (`delta.reasoning_content`/`delta.reasoning`) в перевод не попадают, но считаются живой работой: `beforeLen` считается как `text.length + reasoningChars`, иначе сторож «нет токенов» убивал долгое размышление, а прогресс молчал вместо «💭 модель размышляет…». Пингу проверки размышления тоже считаются ответом.
- **Ошибка внутри SSE-потока разворачивается** (`streamErrorInfo`): роутеры кладут её строкой с JSON внутри, `{"error":"{\"error\":{\"message\":…},\"code\":400}"}`. Без разворота пользователь видел экранированный JSON, а потерянный код 400 заставлял повторять заведомо плохой запрос `maxRetries` раз.
- **Отменённый/оборванный прогон — не «идущая» панель**: готовая глава и отмена гасят панель сами, оборванный перевод остаётся с `nm-rp-done` и кнопкой «Скрыть», в читалке — заглушка «⏳ Перевод не завершён • ⋮ → «🌐 Перевести» продолжит с сохранённого места».

## 3б. Настройки Lite (v1.44) — что нельзя ломать

- **Внутри «Настроек» — вторичные вкладки** (`.nm-subtabs`/`.nm-subtab-content`, порядок `main → reader → translate → advanced`): «Основные» (API, языки, сеть), «Читалка», «Перевод» (чанк, автоперевод, опции глоссария), «Продвинутое» (reasoning, промпты). Открытая вкладка — клиентское предпочтение `settingsSubTab`, оно лежит в конфиге (у Lite хранилище одно). Порядок вкладок и панелей обязан совпадать.
- **Модалка шелла — flex-колонка**: шапка с заголовком и ✕ и подвал со «Сбросить настройки» и `#status-settings` неподвижны, скроллится только `.nm-modal-body`; подвал — `position: sticky` внутри тела, иначе кнопка и индикатор уезжают за экран на длинных вкладках.
- **Подсказки — иконки (?), а не `<small>` под полем**: `data-tip` на `.nm-hint`, показывает их один общий `#nm-tip` (`position: fixed`, appended в `#nm-root`) — вложенный в скроллящуюся модалку tooltip обрезался бы `overflow`. Правила: hover/`focusin` показывают, `focusout`/клик мимо и Escape прячут, на тач-устройствах (`(hover: none)`) подсказку переключает тап; без `#nm-tip.active { display: block }` тултип остаётся невидимым.
- **Чекбоксы — карточками** (`.nm-check-card`): `label` растянут на всю строку, зона клика — весь текст, подсказка карточки стоит вне `label` (кнопка внутри label переключала бы чекбокс).
- **Валидация числовых полей (`parseNumSetting`)**: не-число/пусто → значение по умолчанию, вне диапазона → граница; в обоих случаях поле получает `nm-input-bad` и `aria-invalid`, а `#status-settings` печатает причину и применённое значение. Проверка навешана и на `blur`: в `input[type=number]` браузер буквы не принимает вовсе и события `input` не бывает, так что без проверки на выходе из поля «тихая подмена дефолта» осталась бы невидимой. Границы `min`/`max` в разметке и в спецификациях парсеров обязаны совпадать (это сторожит `lite-settings.test.mjs`).

## 4а. Reasoning / thinking (v1.43)

- Единого поля у провайдеров нет, поэтому в `120-http.js` — реестр `REASONING_PROFILES` (`openai`, `anthropic`, `qwen`, `dashscope`, `ollama`, `openrouter`, `all`) и `reasoningFields()`: режим (`default`/`on`/`off`) + уровень + бюджет превращаются в ключи выбранного профиля. Профиль отправляет **только свои** ключи (незнакомый ключ часть серверов считает ошибкой запроса), «все сразу» — отдельный осознанный режим.
- `default` + пустой уровень = ни одного reasoning-ключа (историческое поведение; старое значение `None` читается как «не отправлять»). Свои поля (`extraBodyJson`) добавляются в тело последними и перекрывают reasoning-ключи — это универсальный способ для любого провайдера.
- **openrouter: `effort` и `max_tokens` — что-то одно**, не оба сразу (проверено на routerai: вместе — ошибка в потоке, 0/12 запросов; по отдельности — 12/12).
- **Живые проверки на routerai** (`access-control-allow-origin: *`, так что трафик Lite идёт режимом по умолчанию): чужие reasoning-ключи роутер молча игнорирует (65/65 запросов — 200), поведение переключателя диктует апстрим (`reasoning:{enabled:false}` выключает по-настоящему, `reasoning_effort: none` для qwen — нет), а размышления приходят полем `delta.reasoning` (+ `reasoning_details[]`).
- Что реально уходит в запрос, печатает «🔌 Проверить сервер» (`💭 как у модели` / `💭 qwen: chat_template_kwargs={…}`). При `thinkingMode: 'on'` пинг не шлёт `max_tokens: 1`: часть серверов требует `max_tokens` больше бюджета размышлений.
