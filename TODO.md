- [x] **4. `cli/translate_check.py` — адаптивная проверка объёма в два прохода.** Вместо `--neighbor`/`--original` («ratio±tol») и констант `RATIO_NEIGHBOR/TOL_NEIGHBOR/RATIO_ORIGINAL/TOL_ORIGINAL` — один флаг `--sensitivity` (K, число, дефолт 5 из реестра `TRANSLATE_CHECK_SENSITIVITY`; 0 = объёмные сравнения выключены, работают только размер файла, regexp и последовательность). Единица счёта — токены выбранного токенизатора. Проход 1 (статистика): идём по ВСЕМ главам книги из `build_chapter_map` независимо от `--start/--end`, для каждой пары сравнений выбранного `check_type` (polished → redacted+chapter, redacted → translated+chapter, translated → chapter) собираем отношения объёмов тех глав, где есть оба файла; на каждую пару отдельно: n — размер базы, центр = медиана, MAD = медиана |x − центр|, допуск = max(пол, K · MAD / центр); полы допуска: соседние пары 2%, пары с оригиналом 5% (измеренный разброс книги поверх пола перекрывает его). Проход 2 (флагование): проверяются только главы диапазона, ошибка — если отношение главы вышло за `центр ± допуск`; отчёт по каждой паре пишет единицу и имя токенизатора, размер базы, центр, MAD, итоговый допуск, число глав в книге/в базе/в диапазоне/помеченных. Граничные случаи статистики: у пары нет ни одной полной главы (n = 0) → пара пропускается с явной строкой «статистики нет», остальные проверки главы работают; n = 1 → пара пропускается (центру взяться неоткуда, допуск вокруг единственной главы бессмыслен); 2 ≤ n < 5 → центр = медиана выборки, но MAD не доверяем: допуск = max(пол, 15% для пары с оригиналом, 2% для соседних) — ширина из замеров полной книги, а не обманчиво узкий разброс трёх глав; пустые файлы (0 токенов) в базу не попадают и ловятся `--min-file-size`; у части глав нет промежуточной стадии (переведены 300 из 601, redact делали не везде) → каждая пара собирает свою базу, размеры баз печатаются по отдельности; сломанные/обрезанные главы в базе сдвигают центр только если их больше половины книги (медиана устойчива до 50% битых — это честный предел метода, пишем его в отчёт одной строкой при первом срабатывании); узкий диапазон при широкой базе — статистика всегда по всей книге, флагуется только диапазон (случай «переведены 300 глав, проверяю 1–7» — основной); дубли папок/файлов — существующая логика strict/lenient без изменений; книги без ни одной полной пары — отчёт с нулями и подсказкой, не падение; файлы читаются через `find_chapter_file` с каноном глав, никаких обходов руками.

## Серия «Адаптивная проверка объёма: две ручки, цепочка стадий»

Замеры на боевой книге (601 глава) показали, что одна чувствительность на все пары не бывает верной: у соседних стадий разброс отношения 0.13%, у пары с оригиналом — 4.42%. Пункты 4–8 серии «Адаптивная проверка объёма и токенизаторы» описаны по прежнему замыслу (одна ручка `--sensitivity`, полы 2%/5%, токенизаторы); ниже — как это устроено теперь.

- [x] **Отношение считается в логарифмах.** `M = exp(медиана ln r)`, `σ = 1.4826·MAD(ln r)`, допуск `max(ln(1+пол), K·σ)`, границы `M·exp(±допуск)` — мультипликативные, поэтому 0.9 и 1.111 от медианы 1.0 равноудалены (аддитивный `±N%` делал узкую сторону строже). Числа в отчёте остаются в отношениях: человек сверяет их со строкой ошибки, а не пересчитывает.
- [x] **Две ручки вместо одной.** `--sensitivity-stages K` (дефолт 7, пол 0.5%) и `--sensitivity-original K` (дефолт 3, пол 5%); `0` выключает свою группу, обе в нуле — объёмные сравнения выключены. Реестр: `TRANSLATE_CHECK_SENSITIVITY_STAGES`/`_ORIGINAL`/`MIN_DELTA_TOKENS`. Старый `TRANSLATE_CHECK_SENSITIVITY` не теряется: `ENV_ALIAS` в `core/settings.py` отдаёт его значение `_ORIGINAL` (широкая группа), пока новый ключ пуст; файл не переписывается.
- [x] **Пары строятся по цепочке `polished → redacted → translated → chapter`.** `comparisons_for` отдаёт ВСЕ пары выбранного типа, `present_from` смотрит, какие файлы есть в книге; поэтому у книги без redacted работает пара `polished ↔ translated`, а не только оригинал. Нет промежуточной стадии — пары просто нет: «эталон не найден» из отчёта убран.
- [x] **Оригинал — второй эшелон.** Если глава уже разошлась с соседней стадией, отклонение от оригинала не повторяется (это тот же сдвиг); если цепочка ровная, ошибка говорит «правьте оригинал».
- [x] **Порог шума в токенах.** `--min-delta-tokens` (дефолт 150): `|check_n − M·ref_n| < 150` ошибкой не считается — 2% на главе в 200 токенов это округление оценки, а на 3000 токенов уже ловится.
- [x] **Подсказка к выбросу одна на отчёт и на предрасчёт** (`volume_hint`): «пройдёт при K ≥ N», а сверх `MAX_HINT_K = 20` — «правьте главу: это Nσ разброса книги», при нулевом разбросе — «K не поможет: допуск держит пол».
- [x] **Предрасчёт в форме запусков.** Кнопка в строке первой ручки (`tcStatsWidget` в `web/static/run-views.js`) зовёт `POST /api/stages/translate_check/stats`: те же функции, что у прогона, но главы не читаются. Ответ — по строке на пару (допуск, медиана, число глав, свой K) и главы диапазона вне допуска с той же подсказкой. Правка ручки делает ответ старым («поля изменились — пересчитайте»); обе в нуле — «объёмные сравнения выключены».
- [x] **Отчёт и шкала.** `stats_line` печатает `глав N, медиана M, разброс X%, допуск ±Y% → отношение lo–hi (K=K)`; пары с нулевой базой не печатаются вовсе, выключенные — «выключено (чувствительность 0)». Шкала отчёта печатает три знака (`0.991–1.009`): при текущем разбросе двух не хватает, чтобы полоса была полосой.
- [x] **Проверка серии.** `./dev.sh test` — 2623 теста, `./dev.sh spa` — `node --check` и `node --test` чисто, `./dev.sh probe --shot` — все экраны чисто; у полигона сценарий «предрасчёт» проверяет две ручки, свой K у пары, отсутствие `null` в разметке и пометку «пересчитайте». Прогон на реальной книге (601 глава, 3.9 с): `polished vs redacted` — медиана 1.000, разброс 0.13%, допуск ±0.91% → 0.991–1.009; `polished vs chapter` — медиана 1.467, разброс 4.42%, допуск ±14.19% → 1.284–1.675.

## Серия «Допуск объёма в процентах: две ручки вместо коэффициента»

Чувствительность `K × σ` оказалась непрозрачной: человек вводит число, которое умножается на разброс книги, а итог зависит от книги — на одной 7 даёт ±0.9%, на другой ±3%. Теперь ручки задают допуск напрямую в процентах от среднего отношения по книге, то есть ровно то, что человек и хотел сказать.

- [x] **Допуск — процент, а не коэффициент.** «Проверка перевода» считает среднее пары как медиану отношений объёма (устойчива к битым главам) и помечает главу, если отношение вышло за `среднее × (1 ± Д%)`. `--tolerance-stages` (дефолт 5%) и `--tolerance-original` (дефолт 20%): у соседних стадий текст почти не меняется, у пары с оригиналом объём русского и исходного текста расходится в разы. `0` по-прежнему выключает свою группу. Разброс книги (MAD) считается и печатается справочно — на допуск он не влияет.
- [x] **«Мин. отличие токенов» убран.** Порог шума `--min-delta-tokens` (и `min_fix_length`-подобная логика) больше не нужен: допуск задан в долях, и решение «это округление оценки или ошибка» принимает процент книги, а не абсолютная величина. Побочный эффект принят сознательно: на главе в 100 токенов допуск ±5% — это ±5 токенов, и округление оценщика может её пометить.
- [x] **Ключи реестра переименованы жёстко, без алиасов.** `TRANSLATE_CHECK_SENSITIVITY_STAGES`/`_ORIGINAL` и `TRANSLATE_CHECK_MIN_DELTA_TOKENS` заменены на `TRANSLATE_CHECK_TOLERANCE_STAGES` («5») и `TRANSLATE_CHECK_TOLERANCE_ORIGINAL` («20»); старый `TRANSLATE_CHECK_SENSITIVITY` тоже убран, `ENV_ALIAS` пуст. Миграции нет намеренно: `SENSITIVITY_STAGES=7` под новой семантикой означало бы 7%, и старый `.env` тихо сменил бы поведение проверки. Комментарии `templates/.env.example` переписаны.
- [x] **Предрасчёт убран целиком.** Кнопки «Предрасчёт» в форме запусков больше нет: маршрут `POST /api/stages/translate_check/stats`, `_translate_check_stats`/`_sensitivity`/`_int_or_none` в `web/api_stage.py`, `_import_translate_check` в `web/api_common.py`, `tcStatsWidget`/`TC_KNOBS`/`TC_SIG_FIELDS` в `run-views.js` и стили `.tc-stats*` удалены. Ответ на вопрос «сколько глав поймает допуск» даёт сам прогон: шапка отчёта печатает границы, а шкала в «Проверках» — точки вне допуска. Вместе с предрасчётом ушли `collect_book_stats`, `outliers`, `stats_payloads`, `volume_hint`, `min_k_for`, `MAX_HINT_K`; строка ошибки называет границы и допуск, но больше не советует «пройдёт при K ≥ N».
- [x] **Мелкие базы больше не требуют своей математики.** При фиксированном проценте полы `SMALL_N`/`SMALL_FLOORS` (2%/15% для 2–4 глав) и полы `FLOORS` (0.5%/5%) не нужны: форма показывает 5%, и прогон применяет те же 5% — без расхождения «в форме одно, в отчёте другое». База меньше двух глав по-прежнему не даёт пару («статистики нет»).
- [x] **Оригинал сравнивается с проверяемым типом, а не с нижней стадией.** `comparisons_for` строит пары от выбранного типа: стадии ниже дают соседние пары между собой, а `chapter` ставится в пару с самим типом — `polished` → `polished↔redacted`, `redacted↔translated`, `polished↔chapter`; `redacted` → `redacted↔translated`, `redacted↔chapter`; `translated` → `translated↔chapter`. Раньше оригинал висел на самой нижней стадии (`polished` → `translated↔chapter`), и проверка `polished` судила не выбранный файл, а перевод. `check_chapter` идёт по парам со своими путями (кэш `paths` по типам пар), `stats_line` и шкала «Проверок» получают по строке на пару, шапка отчёта печатает `Стадии` и `Пары`. Ключ статистики — низ пары; низы не повторяются, поэтому строки не сливаются. Тесты: `test_comparisons_for`, `test_chapter_pair_hangs_on_check_type`, `test_chapter_pair_base_is_check_type` (база пары с оригиналом — файлы проверяемого типа); ручной прогон на книге в 601 главу — `polished` дал три пары (`polished vs chapter` — среднее 1.467, ±20% → 1.222–1.760), `redacted` и `translated` — две и одну.
- [x] **Отчёт, шкала и справка.** `stats_line`: `polished vs redacted: глав 100, среднее 1.000, допуск ±5% → отношение 0.950–1.050 (разброс книги 0.13%)`; пара с `0` — «выключено (допуск 0%)». `_parse_check_stats` понимает новое слово «среднее» и форму «разброс книги X%», сохраняя разбор старых отчётов (`медиана`, `MAD`). Шапка шкалы в «Проверках» — `допуск lo–hi при ±tol% · разброс mad%`. `web/static/help.md` переписан: как считается среднее, почему ручек две, почему разброс справочный, почему одна глава не база.
- [x] **Битый архив — общая ошибка модуля.** Ошибки распаковки у бэкендов свои (`ZstdError` пакета, `zlib.error`, `tarfile.TarError`), и наружу они вылетали как есть: с установленным `zstandard` список архивов падал сырым `ZstdError` на первом повреждённом файле вместо подписи «архив повреждён». ## Серия «Состояние книги — в книге, привычки — в браузере»

Всё книжное (параметры стадий, профиль LLM, чипсы, место работы во вкладках) жило в `localStorage`: смена браузера, домена или устройства теряла настройки всей книги, а копия книги их не наследовала. Разделили по природе данных: **на диск — то, что описывает книгу, в браузере — то, что описывает это устройство**. Итог — `./dev.sh test` 2519 тестов, `./dev.sh spa` 217, `./dev.sh probe --shot` чистый.

- [x] **`core/uistate.py` — слой состояния книги на диске.** Состояние книги — её свойство, а не свойство устройства: один файл `tmp/ui_state/state.json` на книгу (`UI_STATE_DIR`, `UI_STATE_FILE`, `UI_STATE_VERSION`, `ui_state_dir`, `ui_state_read`, `ui_state_write`). Файл на устройство делил одну книгу на несколько правд (два компьютера и два домена видели разные диапазоны глав), а каталог рос новым json на каждый браузер, домен и чистку cookie — на боевой книге накопилось шесть. Несколько писателей не теряют правки: запись читает файл и накладывает только присланные ключи, у присланных объектов сливаются поля (правка `chunk_size` больше не отправляет с собой старые `start`/`end`); `None` снимает ключ, `None` внутри объекта — поле; запись возвращает состояние целиком, чтобы снимок клиента не расходился с книгой. Файлы прежней версии (`<id>.json`, `pending.json`) сливаются в общий при первом чтении или записи и удаляются — оставленное до обновления состояние не теряется.
- [x] **Роуты `GET`/`PUT /api/projects/{sec}/{name}/ui-state`.** Хендлеры — в `web/api_projects.py`; GET отдаёт `{data, dir}` — одно состояние для всех браузеров и доменов; PUT принимает `{data}` с изменёнными ключами и отвечает состоянием книги целиком. Проекта нет — 404, тело не объект — 400, ошибка записи — 500. Cookie устройства (`nm_device`) больше не выдаётся, а старая гасится при первом запросе состояния книги.
- [x] **SPA переезжает на серверное состояние.** `UICore.bookState(api, section, name)` — снимок книги: синхронные `getItem`/`setItem`/`removeItem` (ключи прежние, поэтому вызовы вьюх не менялись), сервер — истина, `localStorage` — зеркало до его ответа; запись пачкой через `BOOK_SAVE_DELAY = 500` мс и хвост при `pagehide`. Ответ записи обновляет снимок (`applyServer`), поэтому чужая правка и чужой сброс видны сразу. `projectPrefs` перечитывает ключ при каждой записи — вкладка не возвращает поля, которые успел поправить другой браузер. - [x] **Одно состояние книги вместо файла на устройство.** На боевом два компьютера и два адреса (127.0.0.1 и 192.168.x.x) давали разные настройки: `nm_device` — cookie на конкретный хост, поэтому каждая комбинация «браузер + домен» получала свой файл `tmp/ui_state/<id>.json` и своё состояние, а каталог рос новым json на каждый браузер и чистку cookie (на рабочей книге — шесть). ## Серия «Архив проектов»

Готовые книги занимают место и тысячи файлов, хотя работа по ним не идёт: одна книга — 197 МБ на диске, 13 920 файлов на три проекта, из них 3 010 файлов глав. Упаковка одного проекта в `tar` + `zstd` даёт 197 → 54 МБ и один файл вместо десяти тысяч. Условия: архив обязан оставаться обычным архивом (открывается любым архиватором без программы), распаковка — по требованию, а не на каждый просмотр, и `.git` едет внутрь — иначе теряется история.

Замеры, на которых стоит серия (боевая книга, 601 глава): сплошной `zstd -9` — 25,6 МБ за 0,4 с (все ядра), `zstd -19` — 20,4 МБ за 13,8 с, `xz -T0` — 20,3 МБ за 12,4 с, а `tarfile w:xz` из Python (одно ядро) — 45 с при том же размере; распаковка 128 МБ / 4 864 файла — 0,36 с. `git gc` перед упаковкой сокращает `.git` 56 → 35 МБ (5,3 с), после него весь проект — 54,1 МБ.

- [x] **`core/archive.py` — формат, упаковка, распаковка.** Один файл на проект: `tar` + `zstd` (любой архиватор открывает, `tar --zstd` / `zstd -d | tar -x` / 7-Zip), первым членом — манифест `.nm_archive.json` (`name`, `packed`, `version`, `files`, `bytes`), поэтому «что это за файл» читается из потока без распаковки (11 мс). Бэкенды сжатия по приоритету: `zstandard` (есть `threads=-1`) → stdlib `compression.zstd` (Python ≥ 3.14) → `zipfile` (есть всегда) — кнопка работает в Docker, portable 3.12 и на 3.14 без установки пакета. API: `ARCHIVE_EXT`, `ARCHIVE_MANIFEST`, `ARCHIVE_DIR`, `archive_path`, `archive_manifest`, `pack_project`, `unpack_project`, `archive_size`, `archive_available`, `list_archives`; путь архива — `<раздел>/.archive/<имя>.nmz` (файл не выглядит проектом, в песочницу файлов не попадает, перенос между разделами — переименование). Упаковка пишет `<имя>.nmz.tmp` и `os.replace`; распаковка — в `.tmp-restore/` рядом и `os.replace`; существующий проект с тем же именем — отказ.
- [x] **`git gc` перед упаковкой.** `web/history.py` пишет точки, но никогда не упаковывает объекты: 5 371 рыхлый объект, 56 МБ вместо 35. Зовём `porcelain.gc` перед `pack_project` (и отдельной кнопкой «Упаковать историю» не нужно — это часть упаковки проекта). `*.nmz` и `.archive/` исключаются из контрольных точек (`_EXCLUDE`), иначе архив попадает в историю и каждая следующая точка растёт на его размер.
- [x] **Свойство раздела в `.sections.json`.** Список имён → `[{"name": ..., "archive": bool}]` с чтением старого формата (список строк) без миграции; дефолт `archive: false` у всех, включая DONE — иначе у существующих установок первая же книга уедет в архив без спроса. `load_sections` по-прежнему возвращает имена (его зовут 20 мест), новое — `section_props`, `set_section_props` (обёртки `archive_sections`/`is_archive_section` позже убраны: тот же флаг читает `section_props`).
- [x] **Функции архивации в `core/projects.py`.** `archive_project` (проверка: проект есть, не архивный, нет запуска — проверку запуска делает web-слой), `unarchive_project`, `list_archives`, `archive_info`, `list_projects` с учётом архивных. `rename_project`/`delete_project`/`move_project`/`copy_project` получают ветку «это файл, а не папка».
- [x] **API.** `POST /api/projects/archive` (массово: `{"items": [...], "op": "pack"|"unpack"}`, ответ — что сделано и что пропущено), `GET /api/projects/{sec}/{name}/archive` (манифест и размер), `GET /api/projects/{sec}/{name}/archive/download`, `POST /api/sections/{name}/props`. Занятый проект (`jm.running_on`) → 409; архивный проект не пускает стадии и редактор (409/404 с человеческим текстом).
