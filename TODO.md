## Исследование (диагностика по пунктам запроса)

### Симптомы (вкладка «Запуски», стадия «Проверка перевода (LLM)»)

1. Сразу после запуска — toast-ошибка
   `can't access property "textContent", bar.querySelector(...) is null`;
2. лог «📊 Проверка перевода LLM 0/1» висит внизу при переключении на любую
   стадию слева (даже «Массовые замены»);
3. лог не обновляется и не закрывается даже после завершения; на дашборде
   задача завершена; повторный заход на страницу / перезагрузка — «пропал».

### Корень: один и тот же обрыв SSE-стрима

`web/static/run-views.js::attachStream` — обработчик SSE-события `progress`
делает `page.querySelector(".progress-wrap")`. Первый такой узел в DOM —
**мини-бар «Активный запуск»** (левая колонка, рендерится раньше лог-панели;
`miniBar`, класс `progress-wrap mini`). В мини-баре нет `.progress-label`, и
`paintBar` бросает TypeError → исключение вылетает из цикла чтения стрима →
`catch` показывает toast и вызывает `render()`, но **reader стрима брошен**:

- симптом 1 — сам toast об ошибке;
- симптом 2 — `st.job.status` навсегда остаётся `running` (финальный
  `status`-событие уже не читается), панель лога не закрывается;
- симптом 3 — лог замёрз (стрим мёртв), а дашборд/перезаход читают
  `GET /api/jobs` и видят реальный статус.

Прогресс «0/1» — это первое событие `emit_progress(0, len(batches),
"Проверка перевода LLM")` в `scripts/translate_check_llm.py:1049` (один батч);
на нём стрим и падает (в snapshot при attach — то же самое).

### Соседние проблемы того же семейства (проверено)

- **event-обработчик** строит селектор
  `.ch-row:nth-child(${ev.id}) .ch-cell:nth-child(${ev.stage + 1})` — при
  событии не-pipeline (нет `id`/`stage`) `querySelector` бросит SyntaxError →
  тот же обрыв стрима. Таблица глав рендерится при `st.stage === "pipeline"`
  и ЛЮБОМ активном запуске — латентный баг.
- **Дублирование событий**: `attachStream` предзагружает `GET /jobs/{id}`
  (события), а snapshot стрима отдаёт их повторно — `st.events` растёт
  вдвое (таблица не страдает: `chapterByKey` дедуплицирует по `id:stage`).
- **Мини-бар не обновляется живьём** из SSE (застывает на снапшоте).
- **Тулубар лога не показывает, чей это лог** — при переключении стадий
  непонятно, к какому запуску относится панель.

### Прочие места — проблем НЕ найдено

- `project-views.js` (M1-watcher, reviewView) — поллинг API без DOM-крашей;
  `querySelector`'ы загардены (`panel && panel.querySelector(...)`);
- `app.js` — `oldPage` гардится, модалки — `querySelectorAll`;
- других SSE-стримов нет (только `run-views.js`); серверный стрим
  (`web/api.py::_jobs_stream`) корректен: на терминальный статус шлёт
  `status`-событие и закрывает поток.

## Ручная приёмка (через web)

1. Запуск «Проверка перевода (LLM)»: НЕТ toast-ошибки; лог наполняется;
   «📊 Проверка перевода LLM 1/1 …» сменяется завершением; панель лога
   закрывается сама.
2. Во время запуска переключить стадию слева («Массовые замены»): лог
   остаётся (по дизайну), но обновляется и закрывается по завершении;
   в тулбаре видно название запуска.
3. Мини-бар «Активный запуск» слева показывает живой прогресс.
4. Запуск «pipeline»: таблица глав обновляется без дублей; запуск
   не-pipeline стадии при выбранной стадии «pipeline» — таблицы нет.
