## Миграция на внешние библиотеки

Политика (AGENTS.md §2) остаётся «stdlib + минимум зависимостей», но она перестала быть «только stdlib»: библиотека теперь не враг, а инструмент, который обязан (1) иметь fallback или быть обязательным и установлеваемым офлайн из `requirements.txt`, (2) не тянуть за собой сборочных цепочек, (3) не ломать кроссплатформенность. Ниже — итог разбора списка-потока: что принято, что отклонено и почему решение принято именно так.

### Сделано

- [x] **httpx — основной HTTP-транспорт LLM, `requests` — фолбэк.** Роль одна, кандидата два: есть httpx — работает он (один клиент на процесс = переиспользование соединений: конвейер бьёт сотнями запросов в один хост, раньше на каждый уходил handshake; HTTP/2 multiplexing; раздельные connect/write/read таймауты вместо одного числа); нет — requests, который есть почти во всех дистрибутивах. Разницы вызывающий не видит.
- [x] **`core/transport.py` — единая точка выхода в сеть.** Контракт один: `open_stream()` → `ResponseStream` (`status_code`, `headers`, `iter_lines()` — байтовые строки SSE без терминатора). Исключения бэкендов нормализованы к `TransportError`/`ConnectTimeout`/`ReadTimeout`/`BrokenStream`, гигиена стрима и политика ретраев (H3: только 408/425/429/5xx + Retry-After) остались в `core/common.py` и от бэкенда не зависят. Прямой `import requests`/`import httpx` вне `core/transport.py` запрещён — страж `tests/test_architecture.py`.
- [x] **`core/deps.py` — реестр зависимостей вместо доки-таблицы.** Роль закрывается любым из её бэкендов; `degraded` = роль на фолбэке (не ошибка, просто медленнее). Активный стек печатается одной строкой в логе сервера при старте и в `python3 -m core.deps` — деградация видна сразу, а не по «почему NER такой медленный».
- [x] **venv как штатный режим разработки: `dev.sh`.** Свежий системный Python обычно PEP 668 («externally-managed») — pip в него не ставит. `./dev.sh setup|deps|test|run|shell|clean`; скрипт активирует окружение, поэтому команды в коде и доках остаются `python3 …` (AGENTS §2). Каталог `.venv` уже был в `.gitignore`.
- [x] **Локальные библиотеки SPA — под манифестом.** `web/static/vendor/vendor.lock.json`: имя, пакет, версия, лицензия, homepage, происхождение (`url`/`bundle`), sha256 и размер каждого файла; `tools/vendor_assets.py check` — гейт: файлы совпадают с манифестом, в `index.html` нет ни одной ссылки на CDN, удалённая библиотека не вернулась. `fetch` качает декларированный URL и требует явного `--yes` на смену хэша — «обновили библиотеку» теперь diff манифеста.
- [x] **Мусор из вендора убран:** `alpine.min.js` (44 КБ) удалён — SPA на ванильном JS после отказа от Alpine, файл не подключался нигде; в `RETIRED` он числится навсегда.
- [x] **Тесты:** `tests/test_core_transport.py` (выбор бэкенда, нарезка SSE — в том числе строка, разорванная между чанками, и хвост без `\n`, нормализация ошибок, живой раунд-трип через stdlib-сервер на обоих бэкендах), `tests/test_tools_vendor.py` (вендор == манифест, офлайн-гейт), мок LLM в тестах переехал на seam: `core.transport.open_stream` вместо `requests.post`.

### Отклонено (решение осознанное, не «забыли»)

- **python-dotenv.** Наша семантика `.env` шире, чем у него: значения regexp-параметров — чистые `re`-выражения, где `#` — литерал паттерна, а не комментарий (AGENTS §7), плюс `env_overlay` со значимыми пустыми значениями и `WEB_ENV_FILE` из Docker-тома. python-dotenv молча съедает `#` в значениях и раскрывает `${VAR}` — «чинит» то, что работает правильно. Свой парсер — 25 строк, покрыт тестами.
- **tenacity.** Политика ретраев одна и она не про исключения: ретраим по `status_code` из уже открытого стрима и по содержимому (`loop-detected`, `empty`, `cut`, `min_len_ratio`) — см. `stream_chat_completion`. Декоратор с `retry_if_exception_type` описывает другую задачу; ради одной точки вызова он не нужен.
- **psutil.** Снятие дерева процессов закрыто stdlib-кодом (`web/jobs.py::_kill_tree`: POSIX — `killpg` по сессии `start_new_session`, Windows — `taskkill /T`), оно покрыто тестами и платформ не плодит. psutil добавил бы бинарное колесо (C-расширение) и третью ветку остановки в самом чувствительном месте — «нажали стоп, процесс должен умереть».
- **uvicorn / fastapi / ASGI-переписывание.** Сервер синхронный и однопользовательский: SSE-соединений ровно столько, сколько открытых вкладок (единицы), рабочих потоков — десятки, стадии живут отдельными процессами (`JobManager`). Синхронный `ThreadingHTTPServer` + keep-alive (`protocol_version = "HTTP/1.1"`) + `daemon_threads` + idle-таймаут (`web/server.py::IDLE_TIMEOUT_SECONDS`) закрывают реальные проблемы; переписывание ~2000 строк web-слоя на ASGI — риск против fail-fast и SSE без измеримой выгоды.
- **waitress.** То же: смена одного WSGI-сервера на другой там, где WSGI нет.
- **htmx.** Наш UI — SPA на ванильном JS со своим роутером и `$`-хелперами; htmx — вторая модель DOM-обновлений поверх первой. Локальный файл на 15 КБ против библиотечного слоя в SPA, которую мы сознательно убрали (Alpine удалён).
- **alpinejs-persist (и Alpine в целом).** От Alpine уходили именно из-за реактивности на слушателях; возвращать её вариантом с localStorage-директивой — отменять своё решение. Предпочтения уже лежат в localStorage.
- **dayjs.** Даты в UI форматируются `Intl.DateTimeFormat` (stdlib браузера, локализация бесплатно); отдельная библиотека под `toLocaleString` не нужна.
- **chart.js.** Graph-представления нет: статистика — таблицы и мини-бары на CSS. Библиотека на ~200 КБ ради графиков, которых никто не рисовал.
- **diff-match-patch.** Сравнение глав в редакторе — своя доп. вкладка на LCS по абзацам; diff-match-patch решает другую задачу (семантический diff для LLM) и весит больше, чем весь SPA-код сравнения.
- **tiktoken.** Тянет BPE-словари из сети, ломает офлайн-установку, и точность не нужна: единица размеров запросов — оценка `estimate_tokens` (±20–30%), смысл параметров в ней согласован.
- **pydantic / attrs / dataclasses-фреймворки.** Конфиг — плоский словарь строк из `.env` + argparse; валидация данных стадий — явные проверки с человекочитаемым отказом. Схема-фреймворк добавил бы слой, который надо объяснять, ради 12 ключей.
