## План: серия «Адаптивная проверка объёма и токенизаторы»

Замена магических констант объёма на измеряемую статистику. Основа — замеры на
боевой книге (601 глава): у соседних стадий отношение объёмов сидит на 1.000
(MAD 0.1–0.4%), у пары «перевод ↔ оригинал» MAD 2.6–3% при любом способе счёта
(байты, символы, встроенная оценка токенов, настоящие токены Gemma4-31b) —
то есть центр распределения надо не угадывать, а измерять по книге, а допуск
считать от разброса этой же книги. Чувствительность — единственный параметр
человека; остальное считает математика.

- [ ] **1. `core/tokenize.py` — реестр токенизаторов: встроенная оценка + внешние файлы.** Источники счёта: `estimate` — всегда доступная `estimate_tokens` из `core/common.py` (запасной вариант на stdlib) и внешние токенизаторы — файлы формата `tokenizers` (HF) в папке `tokenizers/` рядом с общим `.env` (в репо — корень, в Docker — том с `.env`, переживает обновление). API: `available()` → список `{id, title, ok, error}` (id = имя файла без расширения, `estimate` — всегда первый), `count_tokens(text)`, `count_files(paths)` (пакетно), текущий выбор — настройка `TOKENIZER` (см. 2). Токенизатор грузится один раз на процесс (кеш модуля), `encode_batch` без паддинга и усечения, спец-токены не добавляются (BOS в счёт не нужен); счёт одного файла ~3 мс, книга 601×2 файла — ~4 с, повторных проходов нет (за один прогон числа считаются в словарь и переиспользуются обоими проходами проверки). Граничные случаи: библиотека `tokenizers` не установлена → внешние пункты реестра серые с подсказкой «pip install tokenizers», выбран внешний → предупреждение один раз и работа на `estimate`, запуск не падает; файл битый/не читается → в `available()` у него `ok: false, error`, выбор его = тот же фолбэк с предупреждением; выбранный файл удалили после сохранения → фолбэк на `estimate` + предупреждение в логе; файл пустой → 0 токенов; кодировка не utf-8 → `read_text_safe`; смена выбора на лету в рамках одного запуска невозможна (конфиг читается при старте процесса) — это честно пишем в справке поля; кеш загруженного токенизатора сбрасывать не нужно (выбор за жизнь процесса).

- [ ] **4. `cli/translate_check.py` — адаптивная проверка объёма в два прохода.** Вместо `--neighbor`/`--original` («ratio±tol») и констант `RATIO_NEIGHBOR/TOL_NEIGHBOR/RATIO_ORIGINAL/TOL_ORIGINAL` — один флаг `--sensitivity` (K, число, дефолт 5 из реестра `TRANSLATE_CHECK_SENSITIVITY`; 0 = объёмные сравнения выключены, работают только размер файла, regexp и последовательность). Единица счёта — токены выбранного токенизатора. Проход 1 (статистика): идём по ВСЕМ главам книги из `build_chapter_map` независимо от `--start/--end`, для каждой пары сравнений выбранного `check_type` (polished → redacted+chapter, redacted → translated+chapter, translated → chapter) собираем отношения объёмов тех глав, где есть оба файла; на каждую пару отдельно: n — размер базы, центр = медиана, MAD = медиана |x − центр|, допуск = max(пол, K · MAD / центр); полы допуска: соседние пары 2%, пары с оригиналом 5% (измеренный разброс книги поверх пола перекрывает его). Проход 2 (флагование): проверяются только главы диапазона, ошибка — если отношение главы вышло за `центр ± допуск`; отчёт по каждой паре пишет единицу и имя токенизатора, размер базы, центр, MAD, итоговый допуск, число глав в книге/в базе/в диапазоне/помеченных. Граничные случаи статистики: у пары нет ни одной полной главы (n = 0) → пара пропускается с явной строкой «статистики нет», остальные проверки главы работают; n = 1 → пара пропускается (центру взяться неоткуда, допуск вокруг единственной главы бессмыслен); 2 ≤ n < 5 → центр = медиана выборки, но MAD не доверяем: допуск = max(пол, 15% для пары с оригиналом, 2% для соседних) — ширина из замеров полной книги, а не обманчиво узкий разброс трёх глав; пустые файлы (0 токенов) в базу не попадают и ловятся `--min-file-size`; у части глав нет промежуточной стадии (переведены 300 из 601, redact делали не везде) → каждая пара собирает свою базу, размеры баз печатаются по отдельности; сломанные/обрезанные главы в базе сдвигают центр только если их больше половины книги (медиана устойчива до 50% битых — это честный предел метода, пишем его в отчёт одной строкой при первом срабатывании); узкий диапазон при широкой базе — статистика всегда по всей книге, флагуется только диапазон (случай «переведены 300 глав, проверяю 1–7» — основной); дубли папок/файлов — существующая логика strict/lenient без изменений; книги без ни одной полной пары — отчёт с нулями и подсказкой, не падение; файлы читаются через `find_chapter_file` с каноном глав, никаких обходов руками.
