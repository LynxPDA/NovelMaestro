- [x] **Проверка глоссария: LLM может пометить термин на удаление.** Правка перестала быть только «поле old → new»: у записи появилось действие `action` — «патч» (значение по умолчанию, старые файлы именно такие) или «удаление». Запись удаления — `{term, action, old, new:"", reason}` без полей (`field` пустое), `old` — сводка текущих значений (`ner_item_summary`), чтобы человек видел, что улетает. Промпты (встроенные и шаблон `ner_check_prompt.txt`) объясняют протокол и требуют удалять только очевидное: не сущность лора, обычный слово/осколок фразы, полный дубль с тем же переводом; для дублей с разным переводом — унификация, не удаление. `merge_review_entries` дедупит по term+action+field+old+new, `apply_ner_patches` на принятом удалении вычёркивает из ner.json ВСЕ записи термина (identity-дедуп, равные dict-и других терминов не задевает), RAG-режим и `--auto-apply` идут тем же путём. В SPA — одна фабрика `reviewCards`: у удаления свой заголовок, строка diff с подписью и красной чертой, модалка «Что уходит» без поля «Стало».
- [x] **Массовые замены: предпросмотр честный, пробельные правила работают.** Причина была не в расхождении путей (предпросмотр всегда звал `parse_replace_lines` + `apply_rules_segments`), а в том, что показывать он умел не всё. Правила и diff отдаются через `core.common.mark_whitespace` (`·` пробел, `\t` таб, `⏎` перевод строки — перед своим переводом, структура строк сохраняется): удалённый отступ или перенос были пустотой, а правило «^ + -> » (заменить ОДНИМ пробелом) — «ничего не изменилось». Пань предпросмотра показывает заголовок «глава N · папка · тип.txt — изменится/НЕ изменится», каждое эффективное правило отдельной строкой с его счётчиком и длинный keep режет серединой. `apply_rules_segments` больше не считает заменами совпадения, равные своей замене (нулевая позиция у «^ *»), и такие сегменты не подсвечиваются. `trim_rule_left` наконец согласован с `web.stages._replace_lines`: у стрелки срезается только её собственный хвост, пробелы паттерна значимы и перед ним — « +$ -> » означает «хвостовые пробелы строк», а не битый regexp `+$`; строка из одних пробелов остаётся пустым паттерном. Битая строка (нет «->», пустой или некомпилируемый паттерн, битый шаблон замены) — предупреждение и пропуск, а не падение стадии; счётчики и метки правил размечены так же.

## Миграция на внешние библиотеки

Политика (AGENTS.md §2) остаётся «stdlib + минимум зависимостей», но она перестала быть «только stdlib»: библиотека теперь не враг, а инструмент, который обязан (1) иметь fallback или быть обязательным и установлеваемым офлайн из `requirements.txt`, (2) не тянуть за собой сборочных цепочек, (3) не ломать кроссплатформенность. Ниже — итог разбора: что принято, что отклонено и почему.

### Сделано

- [x] **HTTP-транспорт LLM — один, `httpx`.** «Запасной» клиент (`requests`) вычеркнут полностью: второй клиент — это второй адаптер, второй путь обработки ошибок и второй набор тестов ради поведения, которое вызывающий не видит. Один общий `httpx.Client` на процесс даёт переиспользование соединений (конвейер бьёт сотнями запросов в один хост) и раздельные connect/write/read-таймауты.
- [x] **`core/transport.py` — единая точка выхода в сеть.** Контракт один: `open_stream()` → `ResponseStream` (`status_code`, `headers`, `iter_lines()` — байтовые строки SSE без терминатора). Ошибки нормализованы к `TransportError`/`ConnectTimeout`/`ReadTimeout`/`BrokenStream`; гигиена стрима и политика ретраев (H3: только 408/425/429/5xx + Retry-After) живут в `core/common.py` и от бэкенда не зависят. Прямой импорт HTTP-библиотек вне `core/transport.py` запрещён — страж `tests/test_architecture.py` (он же не даёт вернуть второй клиент в pip-список).
- [x] **`.env` читает `python-dotenv`.** Свой парсер был не «25 строк», а собственный диалект синтаксиса. Семантика зафиксирована за библиотекой: `#` вне кавычек — комментарий (значение с решёткой пишется в кавычках, за этим следит `web/api.py::_sanitize_env_value`), `${VAR}` **не** раскрывается (`interpolate=False`), пустое значение — пустая строка. `env_overlay` (окружение > файл) и `WEB_ENV_FILE` из Docker-тома не тронуты.

Каталог `.venv` уже был в `.gitignore`.

Одиночные прогоны — `./dev.sh test -n 0 tests/test_ner.py`.

### Отклонено (решение осознанное, не «забыли»)

- **tenacity.** Политика ретраев одна и она не про исключения: ретраим по `status_code` из уже открытого стрима и по содержимому (`loop-detected`, `empty`, `cut`, `min_len_ratio`) — см. `stream_chat_completion`. Декоратор с `retry_if_exception_type` описывает другую задачу; ради одной точки вызова он не нужен.
- **psutil.** Снятие дерева процессов закрыто stdlib-кодом (`web/jobs.py::_kill_tree`: POSIX — `killpg` по сессии `start_new_session`, Windows — `taskkill /T`), оно покрыто тестами и платформ не плодит. psutil добавил бы бинарное колесо (C-расширение) и третью ветку остановки в самом чувствительном месте — «нажали стоп, процесс должен умереть».
- **uvicorn / fastapi / ASGI-переписывание.** Сервер синхронный и однопользовательский: SSE-соединений ровно столько, сколько открытых вкладок (единицы), рабочих потоков — десятки, стадии живут отдельными процессами (`JobManager`). Синхронный `ThreadingHTTPServer` + keep-alive (`protocol_version = "HTTP/1.1"`) + `daemon_threads` + idle-таймаут закрывают реальные проблемы; переписывание web-слоя на ASGI — риск против fail-fast и SSE без измеримой выгоды.
- **waitress.** То же: смена одного WSGI-сервера на другой там, где WSGI нет.
- **htmx.** Наш UI — SPA на ванильном JS со своим роутером и `$`-хелперами; htmx — вторая модель DOM-обновлений поверх первой. Локальный файл на 15 КБ против библиотечного слоя в SPA, которую мы сознательно убрали (Alpine удалён).
- **alpinejs-persist (и Alpine в целом).** От Alpine уходили именно из-за реактивности на слушателях; возвращать её вариантом с localStorage-директивой — отменять своё решение. Предпочтения уже лежат в localStorage.
- **dayjs.** Даты в UI форматируются `Intl.DateTimeFormat` (stdlib браузера, локализация бесплатно); отдельная библиотека под `toLocaleString` не нужна.
- **chart.js.** Graph-представления нет: статистика — таблицы и мини-бары на CSS. Библиотека на ~200 КБ ради графиков, которых никто не рисовал.
- **diff-match-patch.** Сравнение глав в редакторе — своя доп. вкладка на LCS по абзацам; diff-match-patch решает другую задачу (семантический diff для LLM) и весит больше, чем весь SPA-код сравнения.
- **tiktoken.** Тянет BPE-словари из сети, ломает офлайн-установку, и точность не нужна: единица размеров запросов — оценка `estimate_tokens` (±20–30%), смысл параметров в ней согласован.
- **pydantic / attrs / dataclasses-фреймворки.** Конфиг — плоский словарь строк из `.env` + argparse; валидация данных стадий — явные проверки с человекочитаемым отказом. Схема-фреймворк добавил бы слой, который надо объяснять, ради 12 ключей.
