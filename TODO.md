боевой книге (601 глава): у соседних стадий отношение объёмов сидит на 1.000

- [x] **4. `cli/translate_check.py` — адаптивная проверка объёма в два прохода.** Вместо `--neighbor`/`--original` («ratio±tol») и констант `RATIO_NEIGHBOR/TOL_NEIGHBOR/RATIO_ORIGINAL/TOL_ORIGINAL` — один флаг `--sensitivity` (K, число, дефолт 5 из реестра `TRANSLATE_CHECK_SENSITIVITY`; 0 = объёмные сравнения выключены, работают только размер файла, regexp и последовательность). Единица счёта — токены выбранного токенизатора. Проход 1 (статистика): идём по ВСЕМ главам книги из `build_chapter_map` независимо от `--start/--end`, для каждой пары сравнений выбранного `check_type` (polished → redacted+chapter, redacted → translated+chapter, translated → chapter) собираем отношения объёмов тех глав, где есть оба файла; на каждую пару отдельно: n — размер базы, центр = медиана, MAD = медиана |x − центр|, допуск = max(пол, K · MAD / центр); полы допуска: соседние пары 2%, пары с оригиналом 5% (измеренный разброс книги поверх пола перекрывает его). Проход 2 (флагование): проверяются только главы диапазона, ошибка — если отношение главы вышло за `центр ± допуск`; отчёт по каждой паре пишет единицу и имя токенизатора, размер базы, центр, MAD, итоговый допуск, число глав в книге/в базе/в диапазоне/помеченных. Граничные случаи статистики: у пары нет ни одной полной главы (n = 0) → пара пропускается с явной строкой «статистики нет», остальные проверки главы работают; n = 1 → пара пропускается (центру взяться неоткуда, допуск вокруг единственной главы бессмыслен); 2 ≤ n < 5 → центр = медиана выборки, но MAD не доверяем: допуск = max(пол, 15% для пары с оригиналом, 2% для соседних) — ширина из замеров полной книги, а не обманчиво узкий разброс трёх глав; пустые файлы (0 токенов) в базу не попадают и ловятся `--min-file-size`; у части глав нет промежуточной стадии (переведены 300 из 601, redact делали не везде) → каждая пара собирает свою базу, размеры баз печатаются по отдельности; сломанные/обрезанные главы в базе сдвигают центр только если их больше половины книги (медиана устойчива до 50% битых — это честный предел метода, пишем его в отчёт одной строкой при первом срабатывании); узкий диапазон при широкой базе — статистика всегда по всей книге, флагуется только диапазон (случай «переведены 300 глав, проверяю 1–7» — основной); дубли папок/файлов — существующая логика strict/lenient без изменений; книги без ни одной полной пары — отчёт с нулями и подсказкой, не падение; файлы читаются через `find_chapter_file` с каноном глав, никаких обходов руками.

Файл без своего тега — предупреждение и встроенный промпт (`load_prompt` теперь читает файл, а не выбирает тег; неры, оценка, wiki, translate_book и конвейер говорят об одном и том же).

- [x] **Вердикт доходит до формы.** `POST /api/stages/{key}/prompt-check` собирает argv обычного запуска, дописывает `--check-prompt tmp/prompt_check.json`, читает вердикт и удаляет служебный файл, держит кеш по (книга, стадия, файл, mtime). Проверка стартует при открытии формы, смене файла и сохранении в редакторе; не удалось — тихо: иконка просто не появляется.

- [x] **NovelMaestro Lite v1.51: призрак оригинала, честная проверка сервера и закрытие модалок.** Читалка перестала пустовать перед переводом: пока идёт извлечение терминов и не пришёл первый токен, в ней бледным текстом лежит сам захваченный оригинал главы — абзацы текущего чанка подсвечиваются фоном, а термины (существующие и свежие записи чанка) вспыхивают интервалами. Призрак read-only (ничего не пишет в глоссарий и не считает частоты), поднимается только на живой ветке главы (кэш показывается сразу), гаснет по NER, по первому токену перевода или фейдом 350 мс, снимается `closeReader`; интервалы строит `normalizedMap`/`termRanges` с лимитами 20 вхождений на абзац и 200 mark на прогон, перерисовку коалесит `requestAnimationFrame`. Чанкование NER и призрака — общий `splitByNewlinesRanged` (диапазоны абзацев), прогресс несёт `chunkDone`/`range`/`matched`/`fresh`. «🔌 Проверить сервер» теперь отвечает на вопрос «есть ли нужная модель»: вердикт по `GET /models` (нет — `❌` с похожими id), пинг чата остался только фолбэком на «`/models` не поддержан» (`⚠️ модель проверить нельзя`), кнопка блокируется на время проверки, тяжёлому `/models` дан свой запас 60 с. Модалки закрываются только явно (✕ и кнопка модалки) — клик по подложке ловил случайные клики и выделение текста, выдернутое за пределы окна. Поле ключа API перестало быть парольным (`type="text"` + `-webkit-text-security`, кнопка «глаз», фолбэк на `password`/`new-password` без поддержки свойства, `autocomplete="off"` остальным полям) — браузер больше не предлагает сохранить ключ как логин. Проверка: `tests/test_tools_userscripts.py` (инварианты модалок, маски и тайминга призрака), `tests/tools/lite-ghost.test.mjs` (интервалы, диапазоны чанков, совпадение моделей), полигоны `lite151.mjs` / `lite151b.mjs` / `modalclick.mjs` в Chromium.
- [x] **NovelMaestro Lite v1.54: вспышки терминов по живому потоку ответа.** Призрак перестал красить текст: абзацы чанка не подсвечиваются фоном, вспышка термина гаснет в прозрачность (отгоревший интервал возвращается обычным текстом) — цвет призрака остался единственным признаком. Вспышки идут ровно по записям ответа модели: `takeNerItems` читает накопленный ответ линейно от места остановки и отдаёт каждую запись в момент закрытия её скобки в потоке, `requestNerChunk(..., onItem)` доносит её до `ghostProgress`. Проверка: `tests/tools/lite-ghost.test.mjs` и `tests/test_tools_userscripts.py`, полигоны `ghostmix.mjs` (глоссарий из двух терминов + два новых в потоке: известные молчат, новые вспыхивают, обрывов нет) и `ghostmany.mjs` (30 новых терминов — вспыхнули все).
