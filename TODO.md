## Порядок работ

Релизы v0.3.4+ собираются с синхронизацией `VERSION` отдельным воркфлоу:
`release.yml` по пушу тега выставляет `VERSION` коммитом в `main` и передвигает
тег на этот коммит, поэтому сборка образа и портативки идёт уже из коммита с
правильной цифрой; `docker.yml` дополнительно сверяет `VERSION` с тегом и
падает при расхождении. Раньше `VERSION` обновлял `windows.yml` уже после
пуша тега, и образ v0.3.4 собрался из коммита с цифрой v0.3.3 — в интерфейсе
обновлённого контейнера оставалась старая версия. Пуш идёт через `RELEASE_PAT`
(секрет с scope `contents: write`): действие на дефолтном `GITHUB_TOKEN` не
запускает новые воркфлоу, и передвинутый тег не собрал бы образ.

Релиз 0.3.0 выложен: тег на `main`, образ `ghcr.io/LynxPDA/novelmaestro:0.3.0`
(и `:latest`, `:0.3`), на релизе — portable-zip и оба `.user.js`. По пути
починены сами прогоны: `userscripts.yml` был невалиден (два соседних ключа `env`
в одном шаге — GitHub его не запускал вовсе) и ставил только `httpx` вместо
полного рантайма; шаг релиза в `windows.yml` выполнялся в pwsh вместо bash;
в тестах — f-строка с переносом внутри `{}` (только Python 3.12+) и проверка
живости процесса, которая считала живым зомби.

Dev-сервер переведён на `./dev.sh start|stop|status` с pid-файлом: остановка
паттерном больше не может задеть боевой контейнер (его процесс виден с хоста с
тем же cmdline) — признак «наш» процесс только «жив + не из контейнера + cwd
равен репо».
